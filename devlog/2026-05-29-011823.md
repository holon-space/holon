## Multi-Phase Architectural Migration Plan — Refined After Senior Review

A comprehensive 11-phase (plus baseline) plan to migrate from the god-struct `ReferenceState` to a layered domain model, retire the `sort_key` field across 81 files, and eliminate the generic `VariantMarker` trait spine from PBT infrastructure and production code.

### Context

The codebase has three intertwined architectural debts: `ReferenceState` (1930 lines, ~30 fields) conflates reference oracle with domain logic; `sort_key` (81-file touch surface) is being replaced by a consensus-derived ordering authority; and `VariantMarker<V>` threading through test infrastructure also infects production (`holon-api/src/reactive.rs`). Prior work established domain-as-projection semantics; this plan operationalizes that by building a clean reference oracle, deriving order from authority (not cached fields), and removing the generic-spine constraint.

### What Happened

- **Ran cheap validations** against highest-risk assumptions: confirmed `VariantMarker` spreads into production (generic-spine refactor, not cleanup), confirmed `BlockOrdering` treats org line order as authoritative (fixed-priority rule needs reconciliation), falsified three alarms (Markdown adapter exists, `MemoryBackend`/`BlockTransition` exist, `children_of` already on `ReferenceState:1167`).
- **Added Phase −1** ("Establish green baseline") to quantify and pin suite stability before touching 81 files — project memory shows `org_create_ordering_pbt_full` is NOT reliably green at HEAD.
- **Split Phase 8 into 8a/8b**: additive `children_of` migration + reference-side order source (stays green), then destructive `sort_key` delete (one commit, minimal red window).
- **Renamed domain fragment to `ReferenceDomainState`** to clarify it is the PBT oracle, not the production domain (which remains a logical projection).
- **Split each re-home phase (2–6) into mechanical re-home + invariant-authoring** to avoid hiding work under "pure field" framing.
- **Rescoped Phase 7**: VariantMarker removal is a generic-spine refactor across `sut.rs`, `state_machine.rs`, `slice.rs`, `transition_dispatch.rs`, `invariant_runner.rs`, and production `reactive.rs` — much larger than "cleanup."
- **Added gating decisions**: ordering-authority reconciliation (before Phase 7), watermark-necessity gate (before Phase 10).
- **Captured deferred validations as scheduled tasks** with explicit falsifiability criteria.

### Status

Plan refined and hardened against architectural surprises; ready for team sign-off before Phase −1 begins. Four follow-up validations (ordering authority, hot-path benches, documents tangle destinations, watermark necessity) scheduled as gates within the phase DAG.
