## IVM FILTER (WHERE ...) clause for aggregates

Implemented support for SQL `FILTER (WHERE ...)` clauses on aggregate functions in incremental materialized views, enabling fine-grained row filtering within aggregates (e.g., `sum(revenue) FILTER (WHERE region = 'US')`).

**What happened**

- Added `filter: Option<LogicalExpr>` field to `LogicalExpr::AggregateFunction` and threaded it through `FunctionCall` / `FunctionCallStar` arms in logical.rs; fixed pre-existing bug where `OVER` clauses were silently dropped in `FunctionCallStar`
- Implemented filter auto-lifting: when pre-projection is triggered by a complex aggregate, filter-referenced columns are automatically added to the pre-projection layout to avoid "column not found" errors in sibling aggregates
- Updated `AggregateOperator` with `aggregate_filters: Vec<Option<FilterPredicate>>` field; gated per-row state updates for Sum/Avg/GroupConcat/JsonGroupArray branches; kept `count` unconditional to maintain group-existence semantics
- Added `FilterPredicate::evaluate_static()` helper so aggregates can evaluate filters without instantiating a `FilterOperator`
- Implemented strict rejection for unsupported combinations (Count/Min/Max/DISTINCT + FILTER) with clear error messages; added column-keyed state collision guard rejecting `sum(x), sum(x) FILTER (WHERE x>0)` which would silently double-count
- Fixed pre-existing bug (M1): `sum()` now returns `NULL` (not `0.0`) over zero contributing rows, matching SQLite semantics for empty filtered groups
- Wrote 27 comprehensive sqltests: 16 happy-path (including auto-lift validation) + 11 lockdown rejections

**Challenges**

- **Column-keyed state collision (C1)**: `AggregateState` buckets are keyed by column index, not aggregate index. Adding `filter` changed the Debug-repr-based dedup key, allowing `sum(x), sum(x) FILTER (WHERE x>0)` to coexist undetected. Solved by rejecting at compile time via explicit duplicate-column-different-filter check.
- **Empty-group semantics (M1)**: FILTER decouples "group exists" from "any row contributed", making `unwrap_or(0.0)` reachable. One-line fix in `to_values`.
- **Auto-lift correctness (C3)**: Filter columns must be available before aggregates see them. Implemented `collect_filter_columns()` helper that runs whenever pre-projection is triggered.

**Decisions**

- Deferred Count/Min/Max/DISTINCT + FILTER support with explicit rejections rather than half-implementing; unlocks the immediate need (`json_group_array(...) FILTER (WHERE ... IS NOT NULL)`) without correctness footguns
- Made `aggregate_filters` permissive in tests (empty vec means "all None") to avoid touching 37 test sites

**Status**

All 27 new sqltests pass; all 110 IVM sqltests pass (no regressions); 68 IVM integration tests pass including 2 new cross-session reload tests. End-to-end verified via holon shape queries.
