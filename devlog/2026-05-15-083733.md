## Fixed org-roundtrip parent mismatch in GPUI PBT seed=42

The property-based test was deterministically failing at step 5/6 with a block parent ID mismatch: `block:-9` was parented to `file:index.org` in the reference model but `block:ref-doc-1` in the SUT. This blocked progression to the next failure.

**What happened:**

- Reproduced the failure twice deterministically with `PROPTEST_SEED=42`
- Traced root cause: `WriteOrgFile` transitions that occur **after** `StartApp` were not re-keying `ctx.documents` or updating `doc_uri_map`
- `apply_start_app` (lines 3639–3674) builds the URI→doc mapping and re-keys documents, but the post-startup write path skipped this
- `synthetic_to_parent` (line 3826) read the stale `self.doc_uri_map` instead of the lazy-resolved version that `check_invariants_async` already computes
- Applied two surgical fixes in `crates/holon-integration-tests/src/pbt/sut.rs`:
  1. Changed `synthetic_to_parent` to use `lazy_doc_uri_map` (one-line rebind)
  2. Added the resolve loop to `apply_write_org_file` mirroring `apply_start_app`'s logic
- Test now progresses past step 5/6 to step 4 and hits the next failure from the handoff
