## Senior Code Review: Windowed Snoopy Treasure Migration Plan

A handoff plan for migrating Snoopy integration tests to use windowed test fixtures was reviewed against the actual codebase (e4cf5b1 fork + holon source) to validate assumptions before implementation.

**What happened:**

- Ran critical-path validation against three core claims: TestDispatcher settle machinery, seed-based determinism, and window API availability
- Discovered three **blocking false claims** in the original plan that would have caused multi-day implementation failures:
  - `run_until_parked() + flush()` doesn't handle cross-runtime settle (tokio/backend threads run outside gpui dispatcher); requires fixed-point settle loop
  - Seed doesn't control all randomness—TestApp hardcodes seed 0 and tokio/Turso are uncontrolled; determinism comes from settle correctness, not seeding
  - `cx.deactivate_window()` doesn't exist; blur testing needs a fork commit first and must use `handle.update + dispatch_keystroke` pattern instead
- Verified positive assumptions: test windows do render (draw populates BoundsRegistry), text insertion works via IME fallback, no duplicate-gpui hazard
- Identified eight missing UserDriver trait method mappings and tooling gaps (capture/minimize/bisect parity, per-candidate clean-slate assertions, bug families only real windows catch)
- Fixed logistics issue: deleted `gpui-pbt-speed` worktree requires `jj workspace forget` + re-add before starting

**Decisions:**

- Preserved spike-first plan shape (H7 validation gates remaining work) since structure was sound despite claim errors
- Replaced imperative window manipulation with public API patterns (`handle.update`, `dispatch_keystroke`)
- Added 20× determinism replay validation and cross-runtime settle fixed-point loop as formal Step 4

**Status:** Plan rewritten in place with all false claims refuted and validation protocol embedded; ready for implementation with significantly reduced risk of mid-stream blockers.
