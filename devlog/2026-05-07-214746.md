## Minimizing and Diagnosing a Turso IVM Bug: `block` Matview Row Drop on Redundant UPDATE

The previous session had captured a trace triggering `focus_roots` mismatch in PBT, but the root cause remained elusive. This session focused on fixing the test harness, re-capturing a clean trace, and minimizing it to understand the actual bug.

### What happened

- **Fixed `print_query` panic**: `turso::Value::FromValue for String` uses `unreachable!()` on non-Text columns. Switched to `get_value()` + per-variant formatting to prevent test harness crashes masking the real bug.
- **Fixed subprocess inconsistency detection**: Updated `crashes_with_subprocess` to spawn replay with `--check-after-each --no-break-on-inconsistency`, so IVM drift surfaces in subprocess output instead of crashing silently. Pattern detector now prioritizes `INCONSISTENCY in <table>` markers.
- **Re-captured trace**: Fresh run reproduced the bug (run 3 of 8), yielding `/tmp/trace_v5.sql` (359 statements). Confirmed the surface was `block` matview missing 1 row, not `focus_roots` directly.
- **Minimized to 7 statements**: The minimizer (phases 1–3) eliminated 403/429 prefix, then whittled down to **7 statements / 2.6 KB**. The root cause: a second `UPDATE block_raw SET content = 'D'` (where content was already `'D'`) causes the row to vanish from the hydrating `block` matview, despite remaining in the base table.
- **Saved reproducible minimal case**: Created `devlog/2026-05-07-turso-ivm-focus-roots-minimal.sql` with `?ASSERT` directives that exit(1) when the bug is present.
- **Updated devlog & handoff**: Rewrote the diagnosis (no longer about `DELETE+INSERT` on navigation tables—minimizer eliminated all of those), and synced memory handoff entry + `MEMORY.md` index.

### Challenges

- **Trace length**: Initial capture was 1602 lines. Minimization phases 1–2 were slow but steady; phase 3 (ddmin) completed once the required tables emerged (`events`, `block_raw`, `block_tags`).
- **Surface vs. root cause**: The PBT's reported `focus_roots` mismatch was a downstream consequence of the `block` matview drop. Only by tracking row state through the trace did the actual trigger (redundant UPDATE) become visible.

### Status

Minimal repro identified and saved. Ready to ship upstream bug report and implement Holon-side value-equality short-circuit on `UPDATE block_raw` as a band-aid.
