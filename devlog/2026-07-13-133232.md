## Patching claude-router-proxy to Route Fable Requests by Subscription

**Context:** Two Claude Code Max 20x subscriptions were imbalanced in token consumption. The goal was to route all Fable requests to one subscription and non-Fable requests to the other using the `claude-router-proxy` project.

**What happened**

- Investigated Anthropic's authentication mechanisms and confirmed `claude setup-token` generates one-year OAuth tokens tied to subscription quota (not metered API billing)
- Discovered a blocker in the proxy's source: `src/upstream.rs` hardcoded credentials into `x-api-key` headers, but Anthropic's OAuth subscription tokens require `Authorization: Bearer` instead
- Patched the proxy to add `bearer_auth: true` config option, allowing routes to send Bearer tokens with the required `anthropic-beta: oauth-2025-04-20` header
- Initial testing revealed a second issue: the proxy dropped the client's original `anthropic-beta` header (which declares active features like context-management), causing `400 Extra inputs are not permitted` errors when Fable requests hit the upstream
- Fixed `build_headers()` to forward the client's original `anthropic-beta` and `anthropic-version` headers, only injecting the OAuth beta flag if absent (deduped)
- Wrote `config.yaml` (two routes: `*fable*` → subscription A, catch-all `*` → subscription B), `.env.example`, and `RUNBOOK.md` with setup instructions
- All 90 tests pass; release binary verified to boot and route correctly
- Moved the patched project to `~/Workspaces/ai/claude-router-proxy` with working config and tokens preserved

**Challenges**

- **Bearer token support missing**: The proxy's native design only supported `x-api-key` headers; required adding a new config field and conditional header logic to route via OAuth
- **Header transparency issue**: The proxy was silently dropping feature-declaration headers from Claude Code, causing API validation errors; solved by explicitly forwarding client headers through to upstream with deduplication

**Status:** Proxy is working end-to-end at `~/Workspaces/ai/claude-router-proxy` with both subscriptions active and routing correctly by model.
