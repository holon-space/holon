## Reviewed Plan 2 Implementation Questions Against Sibling Worktree

Clarified design intentions for three questions about the convergence-harness PBT infrastructure in the `subsystem-convergence-pbt` worktree (Plan 2).

- **Verified** that `declare_pbt_convergence!`, `uniform_subset`, and the `SyncAdapter` enum all live in the sibling worktree, not this one
- **Confirmed** `declare_pbt_convergence!` has exactly one user by design — the macro takes no differentiating inputs (`wiring_axes` is a runtime env override, not a second instantiation). Subsumes blessed slice *coverage* but not their *role* (fast guards vs. expensive nightly explorer)
- **Audited** hard-coded `Todoist`/`GMail`/`GCal` in `wiring.rs`: found they're actually inert — default `wiring_axes()` sync section is empty (`vec![]`), and `SyncAdapter` has no production wire-up. The real test MCP server (`FakeMcpServer`) already exists; the product names are vestigial from old Todoist-fake era. Recommend collapsing to generic `SyncAdapter::Fake` mapped to `register_fake_mcp`
- **Explained** `uniform_subset` vs `btree_set`: it's a thin wrapper around `btree_set` specializing for fixed finite domains (closed enumeration via `Union::new([Just(i), …])`) and full powerset distribution. Contrasts with sibling `weighted_subset` (independent inclusion probability), not with vanilla `btree_set`

**Status**: Design questions answered; all three concern Plan 2's convergence harness and are out of scope for the current `f2-stage2-retire-ref` worktree but documented for future reference.
