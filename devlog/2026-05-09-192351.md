## Phase 1 Complete: Cell Foundation & Text Migration

**Context**: Migrating from the old `MutableText` / `BlockContentResolver` pattern to a unified `Cell<T>` / `EntityCellRegistry` abstraction, enabling per-field Loro integration and setting up authority-flip groundwork for Phase 2.

**What happened**:

- Built `Cell<T>` + `CellBacking<T>` trait hierarchy in `holon-core/src/cell.rs` with `TextCellBacking` for rich-text operations (`apply_text_op`, `apply_replace`, remote delta subscription). Added `LwwTextCellBacking` (SQL fallback) that panics on text-rich ops.
- Implemented `BlockCellRegistry` (only knows `"content"` field in Phase 1) + registry trait `EntityCellRegistry` with `live_field_any` lookup and `on_entity_deleted` cache invalidation. Added `Weak`-keyed eviction per Q3 direction.
- Ported `MutableTextInner` → `LoroTextCellBacking` in `holon/src/sync/loro_text_cell_backing.rs`. Filters self-originated writes; subscribes to Loro doc deltas.
- Wired DI: `BlockCellRegistry` resolved in `event_infra_module.rs` (defaults `sql_only()` if no LoroModule); `loro_module.rs` registers Loro-aware variant. (Q1: DI lookup, no builder.)
- Added `BlockOperations::cells()` accessor; rewrote chord ops (`split_block`, `join_block`, `embed_entity`) to read/write through `live_field::<String>(uri, "content")` helpers. Added `on_entity_deleted` hook in `join_block`.
- Migrated all `MutableText` consumers to `Cell<String>`: `EditorViewModel`, `BuilderServices::editable_text`, GPUI/TUI frontends, PBT `sut.rs`. Renamed `apply_local` → `apply_text_op`.
- Deleted obsolete machinery: `BlockContentResolver` trait, `EditableTextProvider`/`LoroEditableTextProvider`, `mutable_text.rs`.

**Challenges**:

- **PBT divergence on join_block**: General E2E PBT smoke run (1 case) flagged a divergence in join sequences after Phase 1. Root cause TBD—likely ordering between async Loro `commit` and synchronous SQL `set_field` (Q8 hypothesis). Flagged for Phase 2 investigation; does not block Phase 1 verification (unit tests all GREEN).
