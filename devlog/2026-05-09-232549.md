## Fixed PBT TypeChars Divergence via Reference-Model Commit & Trim Normalization

The PBT test suite was showing a carry-over divergence in `bulk-1-0` content (`"LM"` in prod vs `"LM lX8G"` in reference model) after `DeleteBackward` operations. This appeared to be a production bug but required investigation.

### What happened

- Reviewed the Phase 1 handoff devlog to understand prior hypotheses (Loro layer race, inbound consumer wipe, etc.)
- Ran PBT in Full mode with trace-level logging to capture actual state transitions and identify the divergence point
- Analyzed `DeleteBackward::apply_to_ref` and discovered it was not calling `commit_active_editor_if_changed()` when `enable_loro` was true (stale comment suggested TypeChars didn't commit, but it does)
- Found that `commit_active_editor_if_changed` in the reference model was not applying the same trim normalization (`normalize_content_for_org_roundtrip`) that the production write path applies via `SqlOperationProvider::trimmed_content`
- Updated `delete_backward.rs` to add the missing commit call
- Updated `reference_state.rs` to apply trim normalization when writing block content
- Verified fix by running both PBT variants (Full: 452s, SqlOnly: 487s) — both now pass regression seeds

### Challenges

- Initial hypothesis space was large (Loro race, inbound consumer, cell registry caching); trace-level logging with actual transitions proved more efficient than setting debugger breakpoints
- The bug was in the reference model itself, not production code, which required careful comparison of `apply_to_ref` implementations across similar transitions

### Decisions

- Skipped the debugger-based approach in favor of trace-level logging to capture the actual state machine trajectory — this proved decisive
- Diagnosis focused on `apply_to_ref` parity across sibling operations (`DeleteBackward` vs `TypeChars`) rather than attempting to reproduce in isolation

**Status**: PBT TypeChars divergence fixed and verified. Both test variants pass. Handoff devlog updated with resolution link.
