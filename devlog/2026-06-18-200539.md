## ho-zj9: holon-macros-test workspace build break (+ unmasked precondition tests)

P1 from the mayor (filed by the refinery): `cargo build --workspace` — the
canonical merge gate — failed on `main`, so the refinery could not certify any
full-workspace merge. Fixing it turned out to uncover a *second* latent defect
that the build break had been hiding.

### What happened

- **Root-caused the build break.** The `operations_trait` proc-macro keys its
  emitted paths on `CARGO_PKG_NAME`: internal crates (`holon`/`holon-core`) get
  `crate::core::datasource::…`, every *external* consumer gets
  `holon_core::{Result, OperationResult, UndoAction, UnknownOperationError}`.
  `holon-macros-test`'s `Cargo.toml` declared `holon`/`holon-api`/`holon-macros`
  but **not** `holon-core`, so the generated `holon_core::` paths were unresolved
  (E0432 + 3×E0433). Phase-3 drift — `holon-core` became its own member crate.
- **Verified the contract against the siblings.** Every other external consumer
  of the macro — `holon-loro`, `holon-filesystem`, and `holon-macros`'s own
  dev-deps (for `operations_trait_tests.rs`) — declares `holon-core`. So the
  macro's contract is deliberate ("external consumers depend on holon-core"), not
  a hygiene bug; `holon-macros-test` was the lone outlier. **Fix = add the dep**,
  matching the design intent (vs. rewriting the macro to emit `$crate`-relative
  paths).
- **Dep fix restored the gate.** `cargo build --workspace` → green (14m24s).
- **Fixing the build unmasked 3 failing precondition tests.** The crate had never
  compiled on `main`, so its tests had never run. The trait fixture declares
  `set_flag(&self, _id: &str, …)` / `set_priority(&self, _id: &str, …)` — the
  leading underscore is the Rust "unused" idiom (the precondition doesn't read
  `id`). But the macro used the *raw identifier* as the StorageEntity wire key,
  so the generated precondition closure looked up `params.get("_id")` while the
  tests (and any real caller) pass `"id"` → required-param extraction returned
  `Err` → `is_ok()` failed. The String-only `delete(&self, id: …)` test passed
  because its key already matched.
- **Fixed the macro to strip a single leading underscore for the wire name/key**
  (`param_wire_name`), applied at all four sites that turn a param identifier into
  a wire string (OperationDescriptor param name, `*_op` constructor key, dispatch
  extraction key, precondition extraction key). The generated *binding* keeps the
  underscore, so the unused-variable lint stays suppressed; only the key/name is
  normalized. → `holon-macros-test` 6/6 green.

### Decisions

- **Add the dep, don't change the macro's path-emission.** Three independent
  consumers already follow the "external ⇒ depend on holon-core" contract; the
  outlier is the bug.
- **Strip-underscore is the right fix for the test failures, not editing the
  fixture.** Removing the underscore from the trait would re-introduce an
  unused-variable warning in the generated closure; inserting `"_id"` in the tests
  would bake a wrong wire contract. Stripping in the macro keeps the binding
  underscore (lint suppressed) *and* makes the wire key the logical name. It also
  fixes a latent **production** dispatch bug: any `_x` param was previously
  unreachable by its logical name `x`.
- **Blast radius confirmed zero for production.** The only macro-processed trait
  declarations with underscore-prefixed params anywhere in `crates/` are the two
  in `holon-macros-test`. For every clean param, `param_wire_name` is the
  identity function, so the generated code is byte-identical.
