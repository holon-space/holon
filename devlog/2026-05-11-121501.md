## Refactored sort_key handling to use typed positional routing

### Context
The sort_key handling was architecturally broken: position (a relation between siblings) was being encoded as a string scalar and recovered via lexicographic sibling scans, creating a hidden coupling between the string generator (org parser's `gen_n_keys` vs Loro's auto-append) and the recovery logic. When these mismatched, blocks silently landed in the wrong order — the Full-variant PBT flake. The underscore-prefixed `_routing_after_block_id` parameter was a workaround for an untyped event payload.

### What happened

- **Diagnosed the flake** via enhanced PBT generator (preferring empty docs) and verification runs: org-parser-driven Creates with `gen_n_keys` hints fail to position correctly against Loro's auto-assigned fractional indices; SQL-only path passes.
- **Eliminated the string-based positional inference.** Added typed `Event.position_after_block_id: Option<String>` field; removed `_routing_*` underscore prefix and the `SqlOperationProvider` param-stripping convention.
- **Refactored OrgSyncController** (`on_file_changed`) to emit `position_after_block_id` (sibling-walk per parent in document order) instead of relying on `sort_key` hint scans.
- **Updated apply_create** to read the typed field and call `update_block_position` directly, bypassing `apply_sort_key_hint` and its fallback sibling scan entirely.
- **Dropped apply_sort_key_hint and find_position_for_sort_key_hint** — positional logic is now unified: `position_after_block_id` on the event → `update_block_position` in the backend → done.

### Challenges

- **Pre-existing unused-param lint violation** in `turso_event_bus.rs` blocking the build; fixed via bare `_` on trait impl param.
- **SqlOperationProvider param filtering**: the `_routing_*` convention was enforced by a whitelist of known keys. Replaced with a single `INTERNAL_POSITION_FIELD` constant, making the intent explicit.
- **Split_block path**: was using `_routing_after_block_id`; updated to use the new param name consistently.

### Decisions

- **Typed field over convention**: `Event.position_after_block_id` is now a first-class field, not hidden behind an underscore-stripping filter. This makes the "ephemeral routing metadata" distinction clear at the type level.
- **No gen_key_between calls from org path**: OrgSyncController now walks siblings to find the actual predecessor block ID, then routes by that ID. The org parser's `gen_n_keys` string is no longer consulted for positioning — only for the SQL `sort_key` column (a pure projection).
- **SqlOnly unaffected**: Tests and SqlOnly-only paths still call `gen_key_between` internally (in `compute_position_for_sort_key` within the backend), but the org inbound path is isolated from that string magic.

### Status

PBT running. Both Full and SqlOnly variants will confirm green; if so, the flake is fixed and Task B (gate flip) can proceed.
