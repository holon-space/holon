## Fixed frontend ghost rows in watch-matview on index.org swap

The layout PBT's `sql_only` variant was failing with stale row IDs appearing in the rendered watch-matview after a structural swap. Initial investigation pointed at Turso IVM (incremental view maintenance), but full SQL trace replay exonerated the database layer.

- **Extracted and minimized the repro** using `turso-sql-replay` tool (4 sub-bugs in the tool itself fixed en route: stale log-target regex, named-param escaping, DDL truncation on indented `--` comments, `SELECT\n` misclassification).
- **Root cause identified**: `ReactiveRenderedRows::apply_event` accumulates row deletions without clearing on Structure events. When a query itself changes (e.g., `index.org` swap changes the SELECT), the new generation's initial snapshot batch (all-`Created` rows) can never delete rows that only the old query returned — rows persist as ghosts.
- **Fix applied** to `crates/holon-frontend/src/reactive.rs`: treat first Data batch of a new generation as authoritative snapshot — apply, then `retain_keys` to drop rows the new query doesn't produce. Locked with regression test `regeneration_initial_snapshot_drops_rows_the_new_query_no_longer_returns`.
