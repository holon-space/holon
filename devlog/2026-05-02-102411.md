## Add `#+ID:` directive support for rename-safe document identity

Empty org files now create stable Page blocks with UUIDs. To ensure those identities survive file renames, we needed to persist the UUID back to disk so subsequent loads recognize the same document.

**What happened:**

- Added `parse_doc_id()` scanner in `holon-org-format/parser.rs` to extract `#+ID: <bare>` from org files, overriding path-derived `file:URI` identity with `block:UUID` when present.
- Modified `render_document_header()` to emit `#+ID: <uuid>` for all `block:`-identified documents, ensuring round-trip stability.
- Updated `OrgSyncController::on_file_changed()` to resolve documents by `#+ID:` first (creating with that ID if missing), falling back to name-chain lookup only when the directive is absent. Added logic to force a render+write when `#+ID:` is missing, persisting the UUID back to disk.
- Fixed reference-model assertions in the PBT to resolve parent URIs from both `#+ID:` lookups and legacy `file:` paths, so synthetic and real org blocks could be compared correctly.

**Challenges:**

- The PBT's `assert_blocks_equivalent` initially failed because reference-model blocks had `file:URI` parents but synced org files now carried `block:UUID` parents (from written-back `#+ID:`). Solved by making the comparison resolve parent URIs through a doc-id map first.
- Had to distinguish "no structural changes" early-returns from "file missing `#+ID:`" early-returns so empty files trigger a write-back on first sync.

**Status:** `general_e2e_pbt_sql_only` now passes all `CreateDocument` and block-divergence checks. Only the pre-existing `BulkExternalAdd` block-not-appearing flake remains (unrelated; documented in MEMORY).
