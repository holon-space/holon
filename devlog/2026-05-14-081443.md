## Debugging and Fixing SplitBlock Production Divergence

**Context:** Property-based testing revealed three interconnected bugs in the `SplitBlock` operation: wrong target block, parent resolution failure, and URI double-prefixing. Reference implementation was correct; production diverged at dispatch time.

**What happened:**

- Set up runtime diagnostics using `eprintln!` instead of LLDB (async state-machine locals caused OOM)
- Captured exact failure path at seed=42: EditorView Enter handler dispatched `row_id="block:ref-doc-0"` (the Page) instead of the focused leaf editor `c2f12z-s`
- Confirmed `block.parent_id()` returns `None` for Pages (missing hydration pass in `get_by_id`)
- Found `EntityUri::block(id)` double-prefixes when `id` already contains `"block:"` prefix
- **Fixed bug #1 (focus dispatch):** Added strict focus check in `editor_view.rs` — now gates Enter capture to only fire when this editor's input has focus (GPUI focus equality, not contains), and dispatches against `services.focused_block()` instead of `self.row_id`
- **Fixed bug #2 (parent resolution):** Added early guard `is_page()` at `traits.rs:744-749` to refuse splitting Pages (operation is invalid — Pages have no real parent)
- **Fixed bug #3 (URI prefixing):** Changed `split_block` signature from `id: &str` to `id: &EntityUri` (parse-don't-validate), added `EntityUri` case to `operations_trait!` macro with proper extraction/borrow/flattening, updated all call sites
- Verified fixes: test now progresses past the broken assertion at `assertions.rs:60`, hits a new assertion at `assertions.rs:133` (sibling block ordering — likely pre-existing Loro tree hydration issue)
- Documented follow-ups: audit all other `capture_action` handlers (Tab, Shift+Tab, Backspace, arrows, Escape) for the same focus-stealing anti-pattern

**Challenges:**

- LLDB OOM'd on async state-machine locals — switched to print-debugging
- Turso revision mismatch in Cargo.lock broke the build — reverted to known-good `0faa82e1`
- Page blocks have `parent_id: NULL` at SQL level but display `__document_root__` via post-query hydration — `get_by_id` skips that pass, causing inconsistent behavior

**Decisions:**

- Use `&EntityUri` throughout the operation trait to enforce prefix-correctness at the type level, not runtime validation
- Dispatch keyboard events against logical focus (`services.focused_block()`) not editor identity, preventing capture-phase races between layered editors
- Treat Page-splitting as a validation error rather than silently succeeding with wrong parent — defensive programming for an operation that should never occur

**Status:** Three bugs fixed; test suite passes `split_block` unit tests; PBT now hits downstream assertion (sibling ordering in Loro tree). Handoff document created with full hypotheses for follow-up debugging. Other `capture_action` handlers flagged for audit.
