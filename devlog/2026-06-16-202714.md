## Subsystem-Shrinking Spike: Implementation & Evidence

### Context
Implemented the subsystem-shrinking property-based test harness to prove that proptest can shrink toward a minimal causal subset of active subsystems, with precondition replay correctly dropping invalidated transitions.

### What happened
- Built `crates/holon-integration-tests/src/pbt/subsystem_shrink.rs` — a `proptest_state_machine` harness where the config is a `BTreeSet<Subsystem>` generated as test input and shrunk toward fewer elements
- Reused the existing `invariants::registry::Subsystem` enum (not a fork), generated via `proptest::sample::subsequence` over an optional `HOLON_PBT_SUBSYSTEMS` universe (default: `Loro`)
- `init_test` builds real `CapMap` with `MemoryBackend` always present; `SutLoroLog` added *additively* iff `Loro` in config
- Seeded three planted-failure runs: `loro_only` (Loro-dependent bug), `memory_only` (Loro-independent), `loro_sync` (Loro + LoroSync transition)
- All five acceptance criteria passed: generation yields Loro on/off; shrink direction correct (Loro-only → retains Loro; memory-only → removes Loro); causal minimization works; precondition replay drops invalidated `LoroSync` transitions (tripwire: 0 fires); no interference with existing slices
- Updated three docs in worktree (PbtCompositionDesign §8.7, Backlog F6, Contributing anti-pattern) per handoff "On success" requirement
- Isolated worktree commit `kwrrolst` with 5 changed files (2 code + 3 docs); verified default workspace remains clean

### Challenges
- **Workspace contamination:** Initially edited docs via main-repo path, mixing them with in-flight memory-slice work in default workspace. Reverted main docs and re-applied only in worktree to preserve isolation.
- **Precondition replay uncertainty:** The `LoroSync` counterexample forced the shrinker to attempt Loro-removal *while a LoroSync transition was present*, requiring the actual `run_selected`/precondition logic to drop that invalidated transition safely. It did (tripwire: 0).

### Decisions
- `BTreeSet<Subsystem>` over struct-of-bools: `subsequence` shrinks by removal, making "fewer subsystems = minimal" inherently directional — no inverse-shrink trap
- Interior-mutable `SutLoroLog` fixture (not real Loro): planted-bug evidence over real CRDT divergence keeps scope tight for proof-of-mechanism
- Default `HOLON_PBT_SUBSYSTEMS=loro` to keep CI cost low while allowing expensive subsystems (frontend/GPUI) to opt in without code changes

### Status
Spike proven and committed in isolated worktree; not yet landed. Mechanism (config-in-state + shrink-toward-fewer + precondition replay) validated. Ready for rebasing onto F2 memory-slice convergence after review. Residual gaps: single boolean axis (not a rich set), static block tree, fragile planted-failure evidence (no CI protection), no selection assertion in `check_invariants`.
