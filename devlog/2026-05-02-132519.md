## Fixing the `wait_for_block_count` Test Infrastructure Bug

**Context:** The PBT test suite was failing with `wait_for_block_count` exiting prematurely due to a counting bug. The accumulator counted all blocks (including Pages), but the predicate compared against non-Page counts only, causing coincidental matches before the file watcher synced.

**What happened:**

- Analyzed the root cause: `acc.state().len()` (pages included) was compared with `==` against `expected_count` (pages excluded), firing on coincidence within sub-millisecond timescales before the second `BulkExternalAdd` synced.
- Considered five fix options: filter pages, change `==` to `>=`, drop CDC shortcut for polling, use seq tracking, or reuse existing wait primitives — all had downsides (extra poll, wrong predicate, added latency).
- Landed on **Option G (keyset superset)**: replace count-based comparison with identity-based comparison (`expected_ids.iter().all(|id| acc.contains_key(id))`), eliminating the page-distinction problem entirely.
- Discovered the keyset approach alone was insufficient: it catches pending creates but not pending deletes (accumulator still holds the deleted block). Added a secondary predicate: `acc.len() == expected.len() + seed_count`, where `seed_count` is the number of production seed blocks (`sentinel:no_parent`, default sidebars) that ref_state doesn't track.

**Challenges:**

- **Initial fix incomplete:** Keyset superset predicate worked for adds but was trivially true for deletes. Required adding a dual predicate combining subset check + total-count match to properly detect both creation and deletion sync.
- **Seed block accounting:** Production seeds aren't in ref_state but appear in the accumulator. Solution: capture a baseline `seed_count` after `StartApp` populates them, then require `acc.len() == expected.len() + seed_count`.

**Decisions:**

- **Keyset-based predicate over count-based:** Avoids any need to distinguish block types. If the expected set (by identity) is fully present and the total count matches (accounting for seeds), sync is complete.
- **Reuse event-driven CDC stream:** Kept the existing `stream.next().await` loop with a 100 ms per-event ceiling instead of polling, preserving the "no wasted 10 ms intervals" design goal.

**Status:** All three PBT variants (`general_e2e_pbt`, `_sql_only`, `_cross_executor`) now pass. Refactored `wait_for_block_count` → `wait_for_blocks_synced` with identity + count predicates, added `seed_count` tracking to `TestEnvironment`, and updated all 7 call sites across `sut.rs` and `phased.rs`.
