## Still flaky after all fixes

Single Full+SqlOnly run: passes once consistently, but **5×
back-to-back stability still 0/5**.

Two failure modes remaining:

### 1. SqlOnly: "Org file diverged from reference"

Pattern: actual blocks read from org files are missing entries that
ref_state expects (e.g. `block:b4h-3-tdm1-98` + its `::src::0` child,
`block:93j32...`, `block:w9u`).

Tried: bumped `signal_quiescence` from hardcoded 5 ms to caller's
`stability_ms` (25 ms) in `wait_for_org_files_stable`. **Did not
help** — the race window is wider than 25 ms.

Real fix needed: gate `wait_for_org_files_stable` on
`WatermarkState.by_consumer["org"] >= snapshot_global` before reading
org files. The existing `OrgSyncIdleSignal` is too local — it only
covers "loop has no event in flight RIGHT NOW", not "all events
emitted before the wait have been processed". Plumbing required:

- Snapshot `WatermarkState.global` at wait start
- Wait for `WatermarkState.by_consumer["org"]` to reach that snapshot
  (or higher) before returning
- Plus a small mtime-stable check after, as today

`crates/holon/src/sync/turso_event_bus.rs:30-31` exposes both fields
publicly; the integration-tests crate would need to subscribe via the
same engine handle it already holds.

### 2. Full: "Backend diverged from reference"

Pattern: `live_blocks` LiveData accumulator (fed from `SELECT * FROM
block` CDC in `setup_all_blocks_watch` at `test_environment.rs:1524`)
is missing entries the ref_state expects.

Same root cause family as #8/#13: the CDC stream is gated on the
`block` matview, which has the IVM consistency window we keep hitting.
The accumulator can disagree with what the synchronous base table
already has.

Possible fixes (didn't ship — both have correctness implications):

- **(a)** Switch the CDC watch to `SELECT * FROM block_raw` — would
  miss block_tags-only changes (e.g., `Page` tag add/remove without a
  block_raw column change), but the test's assertion shape doesn't
  require those. Would close most of this race class.
- **(b)** Same watermark gating as #1 — wait for `cache` consumer's
  watermark to catch up before reading the accumulator.

(a) is simpler and probably correct given the test's assertions; (b)
is the principled fix.
