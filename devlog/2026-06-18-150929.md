## Senior Review: Windowed Focus Invariant Plan

**Context:** A plan to add a windowed focus invariant to property-based testing, with the goal of detecting focus mismatches between engine and UI. The `/senior-review` skill was applied to identify gaps, false assumptions, and vacuity risks before implementation.

**What happened:**

- Verified the mechanical core (increment 4: macro-driven `SutDriver` adapter) against the worktree — all line counts and type names accurate except three factual errors from memory drift.
- Discovered three serious gaps in increment 3b that would allow a vacuous test to land: the windowed loop already exists but needs reframing as "graft onto existing `SimReplayer`" rather than "build from scratch"; the focus-plant mechanism was unspecified; and non-vacuity assertions were wrong (asserting non-Skip instead of ≥1 `Ok` + planted divergence → `Fail`).
- Validated five hypotheses inline: `SimUserDriver` carries `unsafe impl Send+Sync`; only one `impl SutDriver` exists (E2ESut); transitions apply via `UserDriver` not `SutDriver`; `rendered_elements_fresh` is called per-retry; snapshot warmth is incremental per call.
- Elevated five more to tracked validation tasks (V5–V11): focus-plant design, live geometry on retry, fixed-point snapshot, composed catalog integration, non-vacuity assertions.

**Challenges:**

- **Type name mismatch:** Plan referenced `WindowedSimUserDriver` but code has `SimUserDriver` — signaled plan wasn't reconciled against source.
- **Misplaced anxiety:** The `!Send` concern dissolved once I confirmed the driver already carries `unsafe impl Send+Sync`; the *real* hazard is the unsafe lifetime contract on `*const TestApp`.
- **Vacuity trap:** The body `Skip`s in many states; a clean run could pass without proving anything. Required explicit planted focus divergence and ≥1 `Ok` assertion to give the test teeth.

**Decisions:**

- Reframed increment 3b as "graft the composition catalog onto the existing `SimReplayer` loop" rather than building a new loop — dissolves the per-boot `mem::forget` leak concern.
- Made `GpuiDriverComponent`'s engine focus query explicit as a blocking design task (V6) — it must read the *windowed* engine's matview, not copy E2ESut's.
- Pinned the transition safety invariant: transitions → `UserDriver`; `SutDriver` caps are read-only (invariant only).

**Status:** Plan hardened in place with 10 explicit hypotheses (5 validated immediately, 5 as tracked tasks); increment 4 mechanically verified; increment 3b reframed to eliminate vacuity and safety gaps.
