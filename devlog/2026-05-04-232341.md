## Rewired TUI tests to exercise real input pipeline

The property-based test (PBT) for the TUI was skipping the entire input handling layer, allowing regressions to hide. The test was dispatching intents directly to the reactive engine and never calling `AppMain::app_handle_input_event`, which meant modifications like edit, indent, outdent, and task cycling were completely untested.

### What happened

- **Diagnosed the gap**: `TuiUserDriver` was using `engine.dispatch_intent_sync()` fast-path instead of simulating real keystrokes through `app_handle_input_event`. The test renderer had no input channel and couldn't exercise keyboard routing, focus navigation, or edit-state transitions.
- **Designed a new test harness** that mirrors user behavior: shared `AtomicUsize` for focus tracking, shared `Notify` for render-completion synchronization, and `mpsc::Sender<InputEvent>` from driver to renderer.
- **Built `nav_to(entity_id)` helper** that emits Tab/BackTab/Up/Down keystrokes to walk focus to a target entity in the registry, then reads live `last_registry` to confirm arrival before proceeding.
- **Mapped canonical `KeyChord`s to TUI keystrokes**: `Cmd+Enter` → `Ctrl+T` (cycle task), `Tab` → `Alt+i` (indent), etc., via a routing table that decouples from fixture conventions.
- **Added quiescence barriers** to wait for async `engine.dispatch_intent_sync()` spawns to settle between steps, preventing reads of pre-mutation state.
- **Implemented two-stage sync**: render completes when pixels update, then a second wait for the reactive engine's `current_tick()` to advance, confirming side effects are done.
- **Verified the wiring** by intentionally breaking `dispatch_block_op_on_focused` and confirming the PBT now fails on the first indent command—proving the input pipeline is live.

### Challenges

- **Lost-wakeup race in `Notify`**: Created `notified()` before polling, which can miss a `notify_waiters()` between creation and first await. Fixed by explicitly calling `enable()` on the pinned future before the await arm, per tokio documentation.
- **Spawn-vs-render timing**: Every `app_handle_input_event` arm spawns async engine work but returns immediately. A single render barrier only proves pixels changed, not that mutations settled. Solved by adding a second quiescence wait on `HeadlessInputRouter::current_tick()` after each render.
- **Pre-allocated Arcs**: The renderer task was allocating `focus_index`, `render_notify`, and `last_registry` locally, hiding them from the driver. Moved allocation to `tui_ui_pbt::main` and passed Arcs to both tasks via shared state struct.
- **Registry mutation mid-walk**: If focus navigation wraps around a region boundary while the registry is being re-rendered, bounds checks could fail. Bounded nav loops by `2 * max_seen + 1` to guarantee termination without assuming registry stability.

### Decisions

- **Kept `synthetic_dispatch` on engine fast-path** for test setup (initial state seeding), not user simulation. Documented as `LIMITATION`.
- **No mouse support in input driver**: `app_handle_input_event` only matches `InputEvent::Keyboard`; terminal
