## Resolved 1205 Conflicts by Undoing Over-Aggressive Absorb

Removing `frontends/ply` from the jj history created a cascade of conflicts across 909 commits, all concentrated in a single documentation file.

**What happened**

- Ran `jj log -r 'conflicts()'` and found 1205 conflicted commits, with up to 17-sided conflicts in `docs/Testing/BugFunnel.md`
- Checked `jj op log` and discovered the conflicts originated from `jj absorb` after the rebase — all prior operations were clean
- Identified root cause: the `Remove Ply` commit stripped 53 lines of Ply references from `BugFunnel.md`. The absorb operation attempted to push each deletion back into the historical commit that last modified each line, cascading failures across 900+ descendants
- Executed `jj undo` to revert the absorb operation
- Verified resolution: `jj log -r 'conflicts()'` now returns empty; `cargo metadata --no-deps` exits 0; `frontends/ply` is absent from `main`'s tree and history

**Challenges**

- **Over-eager absorb semantics** — `jj absorb` distributed doc-reference removals across the entire history rather than keeping them localized. This is correct behavior for code changes but pathological for documentation cleanup that shouldn't be scattered across 900 commits just because those commits touched the same file.

**Decisions**

- Kept `Remove Ply` as a single commit atop `main` rather than distributing it — the real goal (removing Ply code from the linear chain) is already achieved, and attempting to absorb doc-only changes across deep history produces unmaintainable conflict cascades

**Status**: All conflicts resolved; `frontends/ply` cleanly removed from history; `main` builds. `Remove Ply` commit ready to land.
