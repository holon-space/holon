## Implementing Focus Navigation Invariants for Frontend Slice PBT

Porting focus navigation capabilities into the composed invariant catalog to enable property-based testing of headless frontend navigation without a window driver.

**What happened**

- Verified the make-or-break (Step 0 probe): headless `FrontendSession` navigation updates `current_focus` + `focus_roots` matviews without window/driver — **passed**
- Added `#[capmap_adapter]` to `RefFocus` (plan's claim it already existed was incorrect) and registered it in `ReferenceState::CapProvider::register`
- Created two wire modules (`navigation_focus.rs`, `focus_roots.rs`) and appended to the composed catalog
- Rebound `NavigateFocus` transition from `S: SutHandle` to `S: SutHandle + SutFocusWrite`, avoiding method-name ambiguity by keeping `apply_navigate_focus` in `SutHandle` as `&self` (using `drain_delivery_barrier` instead of the `&mut drain_region_cdc_events`)
- Implemented `SutFocusWrite` and `SutSqlProjection` for `HeadlessFrontendComponent`, including matview read helpers and a focus settle loop
- Added navigation builder to `builders.rs` with minimal ref seeding (journals only, no block-tree alignment needed)
- Created `navigation_pbt.rs` slice with non-vacuity teeth and union proof-of-concept
- Fixed `memory_slice_selects_exactly_the_full_catalog` test by adding both focus invariants to expected-deselected list

**Challenges**

- `SutFocusWrite` and `SutHandle` both declare `apply_focus_editable_text`, risking ambiguity if made a supertrait — resolved by bounding only the macro dispatch impl, keeping the body in `SutHandle`
- `TestContext::drain_region_cdc_events` requires `&mut` but navigate needs `&self` — substituted `drain_delivery_barrier` (already `&self`), since the shared test prep already drains the region CDC mirror before invariant checks
- Minimal ref must seed initial focus to match SUT boot state (journals) — no full block-tree alignment needed since `RefFocus` methods only read navigation history, not block state

**Status**

All plan verification steps passed: Step 0 probe green, navigation slice 3/3 green (non-vacuity + teeth), lib regression 128/130 (pre-existing reds only), native compile green, V3 parity oracles green, gpui windowed green. Navigation invariants fully integrated and tested.
