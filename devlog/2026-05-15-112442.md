## MockPeer Harness & GitHub MCP Endpoint Validation

We needed to establish test coverage for the fan-out path before probing the live GitHub MCP endpoint, and confirm the endpoint works with raw PAT authentication.

**What happened**
- Designed and implemented `McpCallSurface` trait abstraction to decouple the FDW from concrete `Peer<RoleClient>`, enabling mock injection. Swapped 6 prod sites (`mcp_vtable.rs`, `mcp_integration.rs`) to use `Arc<dyn McpCallSurface>` with zero breakage via unsized coercion.
- Built `MockPeer` test harness in `mcp_fanout.rs` with scripted VecDeques per tool and per-URI response maps, plus a call log for assertion. Added 5 regression tests covering single/paired field enumeration, parameter suppression, empty parents, and bulk responses — all pass.
- Wrote `github_probe` example binary using rmcp's `transport-streamable-http-client-reqwest` to probe `api.githubcopilot.com/mcp/`. Confirmed the endpoint accepts raw PAT in `Authorization: Bearer` header (H1 resolved: no OAuth needed).
- Captured tool catalog via probe: `search_repositories`, `list_issues`, `list_pull_requests` exist with their response envelopes and pagination styles.

**Challenges**
- **Heterogeneous response shapes**: `search_repositories` and `list_issues` have JSON envelopes (`items`, `issues` keys); `list_pull_requests` returns a bare array. Current vtable code assumes `extract_path` always points to an array — needs `Option<String>` to handle bare responses.
- **Three pagination contracts, not two**: `search_repositories` uses REST page/perPage with `total_count`; `list_issues` uses GraphQL cursors with `pageInfo`; `list_pull_requests` has no pagination metadata (short-page heuristic only). Single loop in `call_tool_with_params` can't handle all three — vtable extension required.
- **Owner derivation broken**: `list_repositories_for_authenticated_user` doesn't exist (only `search_repositories`); search response has no top-level `owner` field, only `full_name`. Requires either nested column paths (`owner.login` from `owner` object) or client-side string split.
- **Array columns**: Tools return `topics` and `labels` as nested arrays; need JSON encoding support in columns to flatten into TEXT fields.

**Decisions**
- Chose trait abstraction over in-memory rmcp server: smaller prod footprint, same test fidelity for the enumeration logic under test.
- Deferred vtable extensions (nested paths, bare arrays, pagination variants, static args, array encoding) as a coherent follow-up chunk: ~8–12h of work that unlocks full GitHub YAML but stands alone.

**Status**
MockPeer harness is production-ready (66/66 tests pass, workspace clean). GitHub endpoint validated with PAT. Probe output captured; ready to commit the trait, harness, and probe binary as one milestone before tackling vtable v2 extensions.
