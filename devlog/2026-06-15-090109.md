## Refactored `InvNoOrphanBlocks` to drop spurious `SutSqlProjection` bound

The `no_orphan_blocks` invariant was marked as needing both `SutBackend` and `SutSqlProjection`, but it only calls `SutSqlProjection::all_block_ids()`, which queries the same source table (`block_raw`) as `SutBackend::block_raw_snapshot()`. Dropping the redundant bound makes the invariant purely `SutBackend`-dependent, shrinking the E2E cap footprint and simplifying the memory realization.

- **Root cause**: The audit (§8.5) claimed all three structural invariants were purely `SutBackend` without verifying the bodies. `no_orphan_blocks` actually called `all_block_ids()`, creating an orphan bound.
- **Fix**: Derive `all_block_ids` from the id-set within `block_raw_snapshot()` (same write-truth), eliminating the `SutSqlProjection` dependency.
- **Refactored bound**: `S: SutBackend` only (line 46 in `invariants.rs`).
- **E2E impact**: Selection for E2E slices unchanged (still selected where `TursoProjection` wires `min_sut`); memory slice now selects it automatically without special-casing.
