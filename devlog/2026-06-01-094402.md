## Migrate BlockOperations and block-tree helpers from `&str` to `&EntityUri`

**Context**  
The codebase had been bitten multiple times by double-schemed IDs like `block:block:abcde`, which occurred whenever bare `&str` block IDs were re-wrapped with `EntityUri::block(...)`. The initial `BlockOperations` migration left helper traits (`BlockOrdering`, `BlockQueryHelpers`, `DataSource` block-tree methods) still using `&str`/`String`, creating re-scheming hazards at their call sites.

**What happened**

- Added a `debug_assert!` guard in `EntityUri::block()` to panic on any incoming scheme-qualified string, catching double-schemes at their source before migration completes.
- Migrated `BlockOperations` trait method signatures in `holon-core/traits.rs`: all block-id params now `&EntityUri` (or `Option<&EntityUri>`), with `as_str()` conversions only at true storage boundaries (`DataSource::get_by_id`, `set_field`, `BlockOrdering::place`).
- Migrated `BlockOrdering` trait fully (block-specific, high-leverage): all id params and return types now `EntityUri`/`Vec<EntityUri>`.
- Migrated `BlockQueryHelpers` (sibling/child navigation) to `&EntityUri` params; `DataSource` block-tree defaults (`get_children`, `get_descendants`) to `&EntityUri` params, gated by `T: BlockEntity` so todoist/filesystem impls unaffected.
- Fixed trait bodies in `holon-core`: `join_block`'s re-parent loop, `move_up`/`move_down` calls, and a latent `block:block:` in `join_block` (changed `EntityUri::block(&target_id_for_live)` to `from_raw`).
- Updated `MemStore` test impl: added `get_children` override to handle scheme-qualified ids, wrapped all `String` returns in `EntityUri::block()`.
- Migrated SQL and Loro impls (`sql_block_operations.rs`, `loro_block_operations.rs`): updated `BlockOrdering::place`, `place_all`, sibling/child methods; wrapped `Vec<String>` returns in `EntityUri`.
- Fixed `org_sync_controller.rs` (org reconciler): converted `children()` results inline where needed.

**Challenges**

- **MemStore fixture ids**: Tests used bare ids (`"A"`, `"B"`), but the new trait now passes scheme-qualified ids (`block:A`) to helpers. Solved by adding a `get_children` override in `MemStore` that matches on canonical form.
- **Double-scheme in `join_block`**: The body built `EntityUri::block(&target_id_for_live)` where `target_id_for_live` was already scheme-qualified. The new guard would panic; switched to `from_raw()`.
- **Blast radius**: Initially considered migrating the generic `DataSource`/`CrudOperations` layer (200+ call sites), but scoped tighter to `BlockOrdering` + `BlockQueryHelpers` + `DataSource` block-tree defaults (gated by `BlockEntity`), minimizing impact on todoist/filesystem.
