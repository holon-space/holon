## Verified root cause of Full-mode PBT flake and sketched architectural fix

**Context**  
The `general_e2e_pbt` Full variant was failing reproducibly with "Block order mismatch" — first two children of a doc in wrong order — while SqlOnly stayed green. The working hypothesis blamed `apply_sort_key_hint`'s sibling-scan fallback, but the precise mechanism needed confirmation.

**What happened**

- Enhanced the PBT's block generator to prefer empty docs, making the org-parser's `assign_per_parent_sort_keys` path (which emits evenly-spaced fractional keys) trigger more reliably
- Ran Full and SqlOnly variants in parallel (~9 min each); Full failed reproducibly, SqlOnly passed
- Examined failure logs: mismatches on org-parser-generated headline IDs (`block:--`, `block:-6m-7`), not bulk-synthetic ones — confirms the bug is the general org-file path, not specific to `BulkExternalAdd`
- Traced the exact failure mechanism: `gen_n_keys(N)` produces evenly-spaced lex keys (e.g., "20", "40", "60"); Loro's auto-append uses a different FI strategy (e.g., "80"); `apply_sort_key_hint` scans siblings with filter `fi < hint` — when hint="20" and sibling's Loro FI="80", the filter is false, scan finds no predecessor, block goes to position 0, reversing the intended order

**Root cause identified**

`sort_key` conflates two jobs: (1) a stored scalar for SQL `ORDER BY` projection, and (2) a positional intent input for tree moves. Position is inherently relational ("X after Y"), not scalar. Encoding it as a string and recovering the predecessor via lex comparison makes correctness depend on which generator produced the string. The org parser and Loro use incompatible generators — mixing them silently breaks positioning.

**Architectural diagnosis**

The fix is a two-stage migration away from string-based positional inference:

- **Stage 1** (this session): `OrgSyncController::on_file_changed` emits `_routing_after_block_id` for every create (walk `new_blocks_vec` per parent, track last-emitted sibling). `apply_create` already prefers the routing field over hints, so org-parser paths become immune to generator mismatches. Surgical, narrow, doesn't touch chord ops.
- **Stage 2** (separate PR): Retire `apply_sort_key_hint`, `find_position_for_sort_key_hint`, all sort_key write paths; chord ops get typed positional API (`set_position(target, after: Option<id>)`); `Block.sort_key` becomes read-only, populated from `tree.fractional_index` for SQL projection only.

**Status**

Diagnosis verified. Ready to implement Stage 1 (routing field injection in org parser) to unblock Full PBT and Task B gate flip.
