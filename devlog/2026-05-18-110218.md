## Diagnosing the `SwitchViewMode` mode-b rendering divergence

**Context:** After fixing the drawer-toggle hitbox-stacking bug, the layout PBT now surfaces a separate issue where switching view modes renders the content with the *previous* mode's collection variant (list vs. tree) instead of the newly-activated mode's variant.

**What happened:**

- Instrumented `vm_shared_collection` to log data_source pointer, requested collection_expr, and returned ReactiveView pointer
- Ran the minimal failing scenario: `view_mode_switcher > live_block` with mode-a (list) and mode-b (tree), switching to mode-b
- Discovered: mode-a's thunk is called first → builds ReactiveView with `CollectionVariant::list` → arc pointer (say, `0x1234`)
- Then mode-b's thunk is called → *returns the same arc pointer `0x1234`* despite requesting `collection_expr("tree")`
- `vm_shared_collection` caches views by data_source identity, not by collection_expr; both modes share the same `Arc<ReactiveRenderedRows>`, so mode-b lookup hits the mode-a cache entry

**Root cause:** `vm_shared_collection` uses `data_source` as the sole cache key. When both mode-a and mode-b thunks reference the same `Arc<ReactiveRenderedRows>`, the second call returns the first call's view unchanged, preserving `CollectionVariant::list` even though mode-b requests `CollectionVariant::tree`.

**Fix:** Cache lookup must key on *both* data_source identity *and* collection_expr (or hash the expr). Either:
1. Change cache from `HashMap<Arc<ReactiveRenderedRows>, ReactiveView>` to `HashMap<(Arc<ReactiveRenderedRows>, String), ReactiveView>` (if expr is an owned String)
2. Or build views without caching when the collection variant differs (validate that variant matches the cache hit before returning)
3. Or drop the cross-mode-view cache entirely if variants can differ; rely on ReactiveView's internal memoization instead

**Status:** Root cause identified (same pattern as drawer-toggle bug — a shared Arc carrying context that varies between call sites). Fix is straightforward: update cache key in `vm_shared_collection` to include the collection variant. The generator's `vms_shared` arm is correct; the bug is in the view-model layer, not test setup.
