## Clarifying the Plan Review Changes

I've reviewed the agent's edits against the session context. Here's my assessment:

**Clear improvements:**
- Renaming "Signature pinning" → "Failure signature validation" is clearer
- Expanding wall-clock budget section with concrete numbers (paint quiescence ~500ms per candidate, estimated 100–300 shrink candidates = 50–150s) gives useful context
- Adding "Consider memoizing invariant checks" as a performance note is sensible

**Changes I'd revert or reconsider:**

1. **"Remove the incremental generator entirely" (Task 1 caveat)** — The agent suggested deprecating `phased.rs` immediately. I'd soften this to "plan for eventual retirement" because:
   - `PbtPhaseState` is still live in tests; removing it mid-implementation risks breaking existing runs
   - The ADR 0009 endgame mentions it, but it's an optional simplification, not a prerequisite
   - Better: mark it deprecated in docstring, keep it working, migrate existing tests *after* the new path is stable

2. **"Add a separate `--shrink-only` mode"** — The agent added this as Task 3 stretch. It's a good idea but conflates two things:
   - A *regression mode* (re-run a captured failure through shrinking) — genuinely useful, ~40 lines
   - A *shrink-only mode for live failures* — tempting but adds complexity (what if the first run itself doesn't fail? do you capture first, then ask the user to re-run with `--shrink-only`?). I'd defer this.

3. **Signature pinning wrapper size estimate** — Agent kept my "~30 lines" but it's likely higher (~50–70) because you need:
   - Unwrap the panic message on first failure (parsing `thread 'X' panicked at` format)
   - Regex or message-substring matching for the signature
   - A wrapper closure that re-panics conditionally
   - Test coverage so it doesn't silently swallow real failures
   
   I'd bump the rough total from "~1 day" to "~1.5 days" and flag signature validation as the highest-risk task for getting wrong.

**What the agent couldn't know** (and I should have flagged): The wall-clock budget section assumes `paint_quiescence()` hasn't regressed since the windowed minimizer work. That's a hidden dependency — if someone improved quiescence detection since June, the per-candidate time could be much better.

**Bottom line:** The plan is sound and the edits are mostly good — just revert the "remove incremental generator now" and "add shrink-only mode" points, and bump the signature-pinning estimate. Everything else stands.
