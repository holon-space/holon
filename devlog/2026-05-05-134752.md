## Fixed `set_null_flag` panic on LEFT JOIN with materialized views

A panic occurred when executing LEFT JOINs against materialized views in Turso, triggered by the recent IVM LEFT JOIN feature landing.

**What happened**

- Identified root cause: `Cursor::set_null_flag()` in `core/types.rs:2767` only handled `BTree` and `Virtual` cursor variants
- When `OP_NullRow` bytecode executed on a `MaterializedView` cursor (for unmatched left rows in a LEFT JOIN), it panicked with "set_null_flag on unexpected cursor type"
- Added `MaterializedView` arm to `set_null_flag()` that delegates through `btree_cursor_mut()`, mirroring how `op_column` already reads null flags for matview cursors
- Created regression test `matview_left_join_rhs.sqltest` that reproduced the panic without the fix
- Verified all 15 existing IVM LEFT JOIN tests still pass post-fix
- Squashed the fix into the original IVM LEFT JOIN feature commit (`zqmvqskymyxz`) where it logically belongs

**Status**

Fixed and integrated into the IVM LEFT JOIN feature commit. Queries shaped like `LEFT JOIN <materialized_view>` will no longer panic.
