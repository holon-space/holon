## TUI PBT: Resolved inv1 Block-Divergence Root Cause

**Context:** The test battery had two remaining failures: seed=3 (inv1 block-divergence) and seed=1000 (inv14c/B15 flakiness). The inv1 failure was identified as a real production bug buried under test infrastructure noise. Investigation traced it to Loro CRDT merge asymmetries in the reference model.

**What happened:**

- Reproduced seed=3 deterministically and captured the exact divergence: backend had `"wfbqU 66ZW tQKsaFj"` vs reference predicted `"U 66ZW tQKsaFj"` — a 4-character prefix swap
- Traced root cause to **two asymmetries** between production primary and test peer:
  1. **Op type mismatch**: production uses `text.update()` (diff-based, minimal RGA ops) while test peer used `delete(0, len) + insert(0, content)`, producing different Loro merge structures
  2. **Peer ID mismatch**: production primary's peer_id is random `u64` while reference model hardcoded `peer_id=1`, breaking Loro's RGA tiebreaker (lower peer_id wins on concurrent inserts)
- Built focused unit test (`loro_text_update_vs_delete_insert.rs`) confirming both asymmetries produce observable merge differences
- Implemented fix: added `HOLON_LORO_PEER_ID` env var support to `LoroDocument::new()`, set it to `1` in PBT harness, and switched `multi_peer::update_block()` to use `text.update()` for symmetry
- Seed=3 now passes all 50 transitions; 8/8 seed battery passes

**Challenges:**

- **RGA tiebreaking subtle**: Loro's lower-peer-id-wins rule is deterministic but wasn't obvious from error message alone; required tracing op construction and merge order
- **Test infrastructure camouflage**: the parallel test battery masked this with CPU contention false positives; sequential runs made the pattern clearer

**Decisions:**

- Split into two commits: inv14c/B15 filter (existing) + inv1 fix (new) for clean history
- Pinned primary peer_id in tests rather than relaxing invariant, since divergence was real production behavior

**Status:** inv1 failure fixed and split into separate commit. Remaining seed=1000 inv14c/B15 flakiness appears to be test-only timing sensitivity; recommend sequential-mode harness option next.
