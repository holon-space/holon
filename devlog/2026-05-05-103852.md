## Task #3: Promote `block` to a Materialized View

**Context**: The holon schema has 20+ materialized views reading from the `block` table. To enable change-data-capture (CDC) propagation through these views, `block` itself needs to become a matview over a new `block_raw` base table. A preflight verified that Turso now supports chained matviews (G0/G1 fixes shipped), clearing the architectural blocker.

**What happened**:

- **Preflight extended and ran GREEN**: Extended `holon_block_hydration_repro.sql` with chained-matview test cases covering all four patterns holon uses (simple filter, recursive CTE, JOIN, two-hop CDC). All passed; one narrow G3 edge case found (aliased base case in `WITH RECURSIVE` on matview source) but doesn't affect holon's current matview emission.
- **Refactored for easier flip**: Created `block_table_names.rs` with `BLOCK_WRITE_TABLE` and `BLOCK_READ_TABLE` consts. Threaded through 7 writer sites (2 SqlOperationProvider construction points, 3 frontend INSERTs, 2 worker seeds, 1 backend test seed) and 9 reader sites (SUT, MCP tools, cache reader, query filters, matview-watch SQL). Split `CacheBlockReader::load_all_blocks_with_hydration` into correlated-subquery and matview paths.
- **Executed the flip**: Renamed table `block` → `block_raw`, created new `block` matview with all 17 columns in the GROUP BY (case2b shape), updated FKs on junction tables to reference `block_raw`. Restructured schema modules (4 now: Core, BlockJunctions, BlockMatview, TaskBlockingEdges) and updated DI dependency graph.
- **PBT verified**: Updated the test's hand-rolled schema and SqlOperationProvider construction to the new shape. `turso_block_round_trip_pbt` 2/2 GREEN.

**Challenges**:

- **Chained matview hang risk**: Pre-existing skill noted chained matviews have hung. Preflight bisected shapes systematically and confirmed all holon patterns work post-G0/G1; one unrelated edge case (aliased base case in recursive CTE) documented as G3.
- **Column list for matview**: The case2b aggregation only projected a subset of columns initially. Fixed by projecting all 17 columns from the original `block` table in the GROUP BY, so downstream queries see the full schema.
- **PBT schema divergence**: The PBT's self-contained hand-rolled schema didn't match production. Updated it to create `block_raw` + junctions + matview, and flip its SqlOperationProvider to write to `block_raw`.

- **Const-driven table names**: Rather than refactor all readers/writers immediately, added consts that can be flipped in one place. This deferred 9 reader and 7 writer changes to a single session.
