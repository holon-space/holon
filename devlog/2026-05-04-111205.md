## Forking orgize to support hyphenated tags in org-mode headlines

The org-sync parser was silently dropping inline tags containing hyphens (e.g., `:edge-abstraction:`), since upstream orgize only permits `[a-zA-Z0-9_@#%]` in tag characters. The user's corpus contains hyphenated tags in production, so we needed a fix that doesn't wait for upstream adoption.

**What happened**

- Confirmed via minimal reproducer that orgize's parser silently discards hyphenated tags (orgize requires `[A-Za-z0-9_@#%]`; hyphen is missing)
- User decided to fork orgize to `holon-space/orgize` rather than patch around it
- Created fork at `/Users/martin/Workspaces/rust/orgize` with branch `holon`; applied PR PoiScript/orgize#86 pattern (configurable `is_tag_char` predicate in `ParseConfig`) with a more permissive default that includes `-`
- Updated `headline.rs` syntax module to thread `ParseConfig`'s tag-char predicate into the headline tag parser
- Verified all 42 upstream orgize tests still pass
- Updated holon's `Cargo.toml` to point `orgize` at our fork; added commented-out `.cargo/config.toml` stanza for local path override during dev
- Added focused PBT `test_tags_round_trip` that exercises parser/renderer tag invariant in isolation
- Demonstrated the fix: PBT shrinks to hyphenated case `"A-A"` on upstream (fails) but passes on forked orgize

**Challenges**

- Pre-existing PBT failures (source-block `#+END_SRC` escaping, sibling-level mismatches) were unrelated to tags and predated this work — isolated the new tag PBT to avoid confusion
- Needed to verify fork didn't regress upstream behavior — confirmed all 42 orgize lib tests pass

**Decisions**

- Full fork (not thin wrapper) to own the entire org-mode parser; keep package name `orgize` for drop-in compatibility via git dep
- Hyphen-permissive default (beyond PR #86's strict spec) since real usage demands it

**Status**

Hyphenated tags now round-trip correctly. Fork is live at `holon-space/orgize` branch `holon`; holon workspace points at it. New PBT validates the fix; 4 unrelated pre-existing failures remain in the full suite.
