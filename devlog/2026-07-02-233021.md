## Documented Jujutsu Conflict Resolution Skill

**Context:** Created comprehensive documentation for systematic conflict resolution workflows in Jujutsu, covering automated tools, manual techniques, and verification strategies after `jj rebase` operations.

**What happened:**

- Established three core principles: root-first ordering, avoiding `jj edit` on conflicted commits, and mandatory post-resolution verification
- Documented conflict marker styles (`snapshot`, `git`, `diff`) with guidance that `snapshot` format is easiest for AI agents to parse
- Specified four resolution methods: batch auto-resolve via script, mergiraf for 2-sided conflicts, manual marker resolution, and specialized handling for directory renames and upstream deletions
- Created detailed relocation conflict workflow (Method 4) for handling cases where upstream deletes content your commit modified but relocates it elsewhere
- Provided parallel resolution guidance using JJ workspaces within clone-based isolation
- Documented post-resolution verification including build checks, test runs, and cross-diff validation
- Included comprehensive command reference and transfer procedures for moving results back to original repo
- Added reflection checklist for iterative skill improvements

**Decisions:**

- Prioritized `snapshot` conflict marker format documentation since it requires no mental transformation to reconstruct content, contrasting with `diff` format's patch-application complexity
- Structured methods by complexity (automated → 2-sided → manual → specialized edge cases) to guide users toward efficient resolution paths
- Emphasized the "semantic breakage silent sequel" risk—upstream deletions often mask relocation, creating import-path conflicts that won't surface until build verification

**Status:** Comprehensive jj-resolve skill documentation complete and ready for use in conflict resolution workflows.
