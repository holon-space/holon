## LEFT JOIN implementation for IVM matviews

**Context**: Implement LEFT OUTER JOIN support for incremental view maintenance, using a 3-operator subgraph pattern instead of inlining logic into the existing `JoinOperator`. This unblocks holon's `block`-as-matview architecture and the array-aggregation use case (which requires LEFT JOIN + GROUP BY + nullability propagation).

**What happened**:

- **Phase 1**: Wrote 10 sqltest cases (`ivm-left-join.sqltest`) covering empty pre-state, single matches, multi-match transitions, deletions, and batched txns. All fail with expected "LEFT OUTER JOIN not yet supported."
- **Phase 2**: Extended `extract_view_columns()` to detect LEFT-JOIN right-side table refs and clear the `F_NOTNULL` flag on their columns, propagating nullability through the schema layer. Wired into all 16+ `ColumnInfo` construction sites.
- **Phase 3**: Created `match_counter_operator.rs` (~640 LOC) with two btree stores (`L_PRESENCE`, `R_COUNT`) tracking L-row presence and per-join-key R-row counts. Added `EvalState::MatchCounter` variant and `JOIN_TYPE_BIT = 0b11` constant.
- **Phase 4**: Rewrote `LogicalPlan::Join` arm in the compiler to emit a 3-operator subgraph for LEFT JOIN: `InnerJoinOperator` → `MatchCounterOperator` → existing `MergeOperator` (UNION ALL). Unrolled the match-counter state machine (Phase B: R-side transitions; Phase C: L-side delta emission).
- **Phase 5–7**: Incremental testing and end-to-end validation. Holon `block` shape now works; cross-session restore tests `#[ignore]`'d pending Risk-2 (MergeOperator in-memory state not persisted — pre-existing latent bug for all UNION ALL matviews).
- **Phase 8**: Flipped the old rejection sentinel (`array-agg-left-join` in `ivm-array-aggregation.sqltest` now passes instead of expecting error).

**Challenges**:

- **Risk-1 (ON-clause filter pushdown)**: LEFT JOIN with non-equijoin ON-conjuncts like `L.k = R.k AND L.x > 5` requires the match counter to treat `L.x > 5` as an L-only predicate that forces unmatched rows into the null-pad bucket. Rejected via clear compiler error; proper support requires teaching MatchCounter about predicate semantics (out of scope).
- **`[null]` vs `[]` aggregation result**: `json_group_array` on unmatched L-rows produces `[null]` per SQLite semantics. Holon requires `[]`. This requires FILTER support in IVM aggregates (e.g., `json_group_array(tag) FILTER (WHERE tag IS NOT NULL)`), which is a separate engineering project tracked in `HANDOFF_IVM_AGGREGATE_FILTER.md`.

- **3-operator subgraph over inline logic**: Reuses existing `MergeOperator` and respects the "one `return_if_io!` per state" constraint. Precedent: recursive CTEs already emit
