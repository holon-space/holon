## Implemented: Risk-Elimination & Production Write Path

**Context:** The plan called for integrating the Spike harness's write operations into production machinery (`SutEditorMirrorWrite`) and eliminating key architectural risks around shared backends, Loro write parity, and commit observability before collapsing the full test harness later.

**What happened:**

- **Compile-blocking pre-req (Task #4):** Removed dead `enable_atomic_editor_if_unset` references in `frontends/tui/tests/common/pbt_main.rs` — the test binary now builds.
- **Sharing invariant teeth (Task #2):** Added `broken_sharing_turns_block_content_red` — deliberately hands `InProcEditorSut` a separate backend `Arc` to prove the block-content invariant actually observes the commit (not vacuous).
- **Loro write-path parity (Task #1):** Added `loro_write_path_commits_and_matches_ref` — drives type/delete/type through a real `LoroBackend` and confirms `block_raw_snapshot` matches the reference (the historically-buggy path, now explicitly covered).
- **Commit-path teeth (Task #3):** Manually corrupted commit content, confirmed both memory and Loro tests go RED with exact divergence, then reverted — proves the commit genuinely reaches the block store.
- **Core implementation (Task #5):** 
  - `MemoryBackendComponent`/`LoroBackendComponent` now share `Arc<Backend>` via `new_shared` (zero caller churn via delegating `new`).
  - New `InProcEditorSut` impl of production `SutEditorMirrorWrite` — dispatches through real `InMemEditorComponent`, commits via `update_block` with the same normalization as the reference. Includes fail-loud `content_type == Text` guard and explicit comment about unconditional write on caret-0 no-op.
  - `SpikeSut::apply` routes through production `apply_to_sut`; `SpikeMachine::apply` commits after each type/delete transition.

**Challenges:**

- **Unconditional write on caret-0 no-op:** `delete_backward` sets `dirty = true` unconditionally, so gating `commit()` on `editor.dirty()` wouldn't skip the no-op. Content-gating (what the code already does) is the correct approach; added a note in the Design section to prevent future misunderstanding.
- **Regression-file hygiene:** Plant minimization runs with env-gated seeds appended `cc` seeds to the regression file. Restored it to header-only state after verification; default runs don't re-pollute.

**Status:** All five plan tasks done, all 14 subsystem-shrink tests green (including the three new write-path risk-elimination tests). Plant minimization unchanged. The reusable `InProcEditorSut` write cap is proven and ready for the next stage (shared generator and slice migration) that will eventually retire `E2ESut`.
