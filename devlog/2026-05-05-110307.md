## Intermittent: backend tags=`["[]"]`

Run 1 showed the matview returning `tags: ["[]"]` (a one-element list
containing the literal JSON-encoded empty array string) for several
ref-doc-2 children, while a sibling block under the same parent had
correct `tags: []`. Diagnostic in `parse_block_row` was added to
catch the raw `Value` variant on subsequent runs — **did not
reproduce in run 2 or run 3**. The diagnostic has been reverted.

This points at the matview's `COALESCE(json_group_array(bt.tag) FILTER
(WHERE bt.tag IS NOT NULL), '[]')` shape returning either:
- `Value::Array(vec![Value::String("[]")])` (one element, the literal
  string `"[]"`), or
- a mis-typed Turso row where the JSON column was parsed as Array of
  one element rather than the JSON-encoded empty list.

Both are consistent with the Turso panic above derailing matview
state. If the Turso bug is fixed and this still recurs, instrument
the matview output directly with a query.
