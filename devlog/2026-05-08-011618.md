## Fixed `holon-mcp` Configuration to Load Org Files into In-Memory DB

The `holon-mcp` MCP server was starting with an empty in-memory database because `.mcp.json` wasn't passing the org-mode root directory, preventing `Now.org` and its `now-query` block from loading.

**What happened:**
- Diagnosed why `execute_source_block` couldn't find `now-query::src::0` — the running instance had only 11 default scaffolding blocks and Loro disabled
- Traced root cause to `.mcp.json` args: `["--stdio", ":memory:"]` created a fresh empty DB on each start with no `--orgmode-root` flag
- Located the target org root at `/Users/martin/Workspaces/pkm/holon-pkm` containing `Now.org`
- Patched `.mcp.json` to include `--orgmode-root` while keeping `:memory:` for fresh in-memory initialization
- Discovered `/mcp reconnect` reuses the cached subprocess instead of re-reading `.mcp.json`
- Killed the running process (PID 50413) to force a respawn with the new args

**Challenges:**
- The MCP reconnect command doesn't reload config from disk — it only restarts the existing subprocess with cached args, creating a confusing situation where the config appears patched but doesn't take effect
- Resolved by killing the process and explaining that a full Claude Code restart is needed for the new args to load

**Status:** Configuration patched; waiting for full Claude Code restart to spawn `holon-mcp` with the correct args and successfully query `now-query::src::0`.
