## Senior Code Review: Aggregate FILTER Implementation Plan

**Context:** A plan was drafted to add SQL FILTER clause support to Turso's IVM aggregate operator, targeting holon's use case of `json_group_array(tag) FILTER (WHERE tag IS NOT NULL)`. The plan appeared straightforward but contained three load-bearing bugs and several incomplete specs.

**What happened:**
- Read the original plan and traced claims against actual code (logical.rs, aggregate_operator.rs, compiler.rs, filter_operator.rs)
- Validated six critical hypotheses against SQLite 3.51 to expose semantic gaps
- Discovered `AggregateState` is keyed by column index, not aggregate index — making multi-aggregate-same-column scenarios unsafe
- Found Sum+FILTER returns `0.0` where SQLite returns NULL (silent correctness bug)
- Identified `FunctionCallStar` arm silently discards both `filter_over` AND `over_clause` 
- Caught missed destructure site at test line 4718 that would fail compilation
- Verified `compile_filter_predicate` supports only simple predicates (Column op Literal/Column, IS NULL, AND/OR) — rejects NOT, BETWEEN, IN, function calls
- Performed inline validation: empty filtered json_group_array, group_concat, count, sum, avg behaviors against SQLite

**Challenges:**
- **Column-collision invariant (critical):** `aggregate_map` deduplicates via Debug repr, so `sum(x)` and `sum(x) FILTER (WHERE x>0)` both write to `self.sums[col_idx]` — double-counting. Solution: reject same-column-different-filter combinations at view creation with clear error.
- **Persistence format incompatibility:** `filtered_counts` field changes blob format in unpredictable ways. Solution: drop Count+FILTER from v1 (holon doesn't need it).
- **NULL semantics divergence:** Turso's `to_values` emits `0.0` for empty sums; SQLite emits NULL. Solution: one-line check to return `Value::Null` when sum state missing.

**Decisions:**
- **Scope to Sum/Avg/GroupConcat/JsonGroupArray only** — defer Count, MIN/MAX, DISTINCT to v2 and reject them explicitly with clear errors
- **Auto-lift filter-referenced columns into pre-projection** — eliminates fragile "must be in pre-projection" restriction and handles the edge case where no pre-projection exists
- **Explicit same-column-different-filter rejection** — safer than trying to re-key all aggregate state machinery

**Status:** Plan rewritten as v2 with critical bugs fixed, scope tightened to safe subset, and estimate revised from 5–6 hours to ~2 days. Ready for implementation.
