## Multi-Orchestrator Design: Bounce Protocol & Team Mode

**Context:** The `orchestrator` skill assumes a single writer to the jj repo, creating contention when one orchestrator must supervise many agents. We explored whether teams could enable peer orchestrators, and discovered they solve a different problem: enabling the human-collaboration pattern (isolated workers + serialized commit point + author-resolves-conflicts).

**What happened:**

- Analyzed five load-bearing couplings that enforce single-writer: shared integration chain (rebase divergence), coordinated snapshot/update phases (TOCTOU), stateless enumeration scoping (wrong agent steals streams), global `land`/`main` fast-forward, shared build workspace.
- Rejected two options: Option A (just a global lock) insufficient for scoping bugs; Option B (namespace-partitioned peer orchestrators) mechanically sound but premature without a real two-fleet use case.
- **Recommended Option D + bounce protocol:** Keep one lead agent (merge queue role, handles all jj rewrites), add N teammate agents (supervisors, context-rich, never rewrite). On weave conflict, the lead bounces via `op restore` + `repoint`, signaling the stream owner to resolve in their own workspace—mirroring how humans handle PR merge conflicts (author resolves, not the merge queue).
- Implemented `weave --bounce` in `sw.sh`: on conflict, undoes the chain insert, rebases the stream onto current integration tip, and returns rc=2 (bounce signal). `autoweave --bounce` skips bounced streams; `resolve` now handles post-bounce conflicts and repositions `@` back to chain tip.
- Validated B1–B9 experiments in temporary jj repos via sub-agent: clean weaves byte-identical to non-bounce, bounced chains remain pristine (verified under 10–12× stress), foreign WIP survives, zero `@`-divergence, full loop (weave→bounce→resolve→re-weave) closes end-to-end.
- Surfaced and fixed two jj 0.43 hazards: `jj fix` with no `fix.tools` now skips instead of hard-failing; `jj op restore` + immediate `repoint` hits "commit already exists" within one timestamp tick—fixed with bounded retry.
- Folded docs: `stacked-workstreams` SKILL.md + command docs, `orchestrator` SKILL.md with lead/teammate prompts (teammates get one exception: resolving bounced conflicts in their own workspace).

**Challenges:**

- **Timestamp collision:** `op restore` + immediate `repoint` recreated byte-identical commits faster than jj's backend timestamp granularity. Solution: bounded retry with exponential backoff (fail loud after 5 attempts).
- **Formatter-less repos:** jj 0.43 changed `jj fix` with no `fix.tools` to hard-fail instead of skip, silently breaking weaves in repos without formatters and turning the PBT suite red. Solution: catch the error, log a disclosed skip, continue.

**Decisions:**

- **Lead-as-merge-queue, not omniscient:** Bounce protocol moves conflict resolution to the stream owner (who has context) rather than requiring the lead to understand all lanes. This caps supervision at availability, not comprehension.
