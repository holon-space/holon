## MatchCounter I/O Re-entrancy Bug: Reproducer Verified & Root Cause Isolated

**Context:** The IVM system panics when `MatchCounterOperator::eval` is called with uninitialized state after suspending on I/O during btree reads. This occurs in dual-LEFT JOIN materialized views with file-backed storage and DELETE bursts.

**What happened:**

- Integrated `match_counter_uninitialized_repro.rs` into `tests/integration/query_processing/` and confirmed deterministic panic at `match_counter_operator.rs:378`
- Audited all `return_if_io!` sites in the eval call stack; **found 4 broken arms, not 2**: lines 484 and 531 (`RCount` state), **plus lines 612 and 633** (`LRowResolve` state calling `read_l_presence` and `read_r_count`)
- Enhanced differential fuzzer with `LeftJoin` and `DualLeftJoin` view variants to close gap in matview coverage (no LEFT JOIN patterns were being generated before)
- Ran fuzzer across 80+ iterations with `--file-io --batch-probability 0.5`; fuzzer generated LEFT JOINs but did not deterministically trigger I/O suspension path (other unrelated ATTACH bugs shadow it in most runs)

**Challenges:**

- **Fuzzer reproducibility vs. deterministic test:** The bug requires specific page-eviction timing on btree reads within a single `eval` call. Fuzzer's randomized small tables don't reliably push volume through one matview's state index to trigger suspension. Deterministic Rust integration test (already in place) gives strong regression coverage.
- **Root cause audit complexity:** The bug pattern (state not restored after `return_if_io!`) spans 4 code arms across two state types (`RCount`, `LRowResolve`), requiring careful state machine inspection to find all instances.

**Decisions:**

- **Keep LeftJoin/DualLeftJoin fuzzer variants:** Matview coverage is now complete; probabilistic detection of this bug class is acceptable given deterministic test exists
- **Fix all 4 arms, not just 2:** The bug report identified 2 sites; the full audit reveals 2 more with identical symptoms

**Status:** Root cause fully isolated; ready to implement `return_and_restore_if_io!` macro fix across all 4 arms in `match_counter_operator.rs` (lines 484, 531, 612, 633).
