## Validated hypotheses (checked on this tree, not assumed)

- **V1** `watch_query`'s `EnrichedChangeStream` is fully holon-api-typed
  (`EnrichedRow` = holon-api/src/widget_spec.rs:71). The agnostic core trait
  drags no Turso types.
- **V2** `holon::entity_profile::RowProfile` is field-identical to
  `holon_api::RenderProfile`; holon-api already has
  `pub type RowProfile = RenderProfile`. Dedup, not move.
- **V3** `EntityProfile`'s inherent resolve machinery (`resolve`,
  `resolve_with_computed`, `resolve_candidates`, `build_scope`, …) is pure
  rhai + holon-api `Value` — no LiveData/StorageEntity. It **must move with
  the struct** (inherent impls live in the defining crate). rhai feature
  parity verified: holon-api and the workspace both pin
  `rhai = { version = "1", features = ["sync"] }`.
- **V4** `ProfileResolver` (stays in holon) reads `ProfileCache.profiles`
  (private) at 4 sites (entity_profile.rs:1069/1125/1191/1210) and builds the
  map (977–988). Cross-crate privacy ⇒ ProfileCache needs a small pub API:
  `new(HashMap<EntityName, EntityProfile>)`, `get(&EntityName)`,
  (`get_mut`/iteration if 985 needs it). No design change, just surface.
- **V5** `StorageEntity` is `pub type … = HashMap<String, Value>`
  (holon-core/src/storage/types.rs:13). Aliases unify — `OperationEngine`'s
  signature is moveable with zero friction. holon-core's alias stays
  (macro-emitted callers expect that path).
- **V6** Raw-SQL trait-method callers outside holon: integration tests (via
  `self.engine()`), **frontends/mcp/src/tools.rs** (in-workspace! raw
  `engine.execute_query` at :142/:1117/:1496), and holon internals.
  ply/holon-worker/waterui/dioxus* hits are workspace-**excluded** drifted
  frontends (Cargo.toml `exclude`) — out of scope.
- **V7** Single `ProfileResolving` impl (`ProfileResolver`); single concrete
  setter of `ReactiveEngine.block_cell_registry` (sut.rs:838), and the only
  *use* already goes through `&dyn holon_core::cell::EntityCellRegistry`
  (reactive.rs:2026-2032).
- **V8** archlint smells mention `QueryEngine` only in prose, not path
  patterns — no rule edits, just re-run the sweep.
- **V9** Frontend (and holon's `watch_ui::merge_triggers`) use
  `Mutable<Arc<ProfileCache>>` purely as an opaque change signal — nobody
  outside entity_profile.rs reads inside the cache.
- **V10** `CompiledComputedField = (String, CompiledExpr)`
  (type_registry.rs:22); `CompiledExpr` already holon-api.

## Steps (each ends `cargo check --workspace --all-targets` green)

Ordering rationale: dedup first so the moved trait already speaks
`RenderProfile`; small traits before the profile-model move; holon-app
relocations last (they're the only steps touching files the other session
also touches).

### Step 1 — RowProfile dedup (mechanical, workspace-wide)
Delete `holon::entity_profile::RowProfile`; retarget every user to
`holon_api::RenderProfile`. No semantic change. Run holon-frontend nextest
here (cheap regression catch before the big move).

### Step 2 — three traits + QueryEngine split → holon-api
One holon-api module per trait, mirroring holon::api file names
(`query_engine.rs`, `ui_watcher.rs`, `operation_engine.rs`):
- `UiWatcher` — moves verbatim (EntityUri + WatchHandle are holon-api).
- `OperationEngine` — moves verbatim; signature spells the StorageEntity
  alias from a new holon-api `pub type StorageEntity = HashMap<String, Value>`
  (same alias target as holon-core's ⇒ types unify).
- `QueryEngine` — **split**:
  - holon-api `QueryEngine`: `watch_query`, `search_link_candidates`,
    `block_content_by_id`, `lookup_block_path`.
  - holon keeps `trait SqlQueryEngine: QueryEngine { compile_to_sql,
    query_and_watch (RowChangeStream), execute_query }` in
    holon/src/api/query_engine.rs, impl'd by BackendEngine. Retarget its
    callers: holon internals, frontends/mcp/src/tools.rs, integration tests.
Impls stay put: `BackendEngine` (all four), `DispatchingOperationEngine`,
`LoroUiWatcher`, `enrich_*` helpers. `holon::api` re-exports the holon-api
traits (holon remains the impl crate; holon-api the trait home) — retarget
holon-internal paths opportunistically where touched.

### Step 3 — profile model + ProfileResolving → holon-api
New holon-api `entity_profile.rs`: `VirtualChildConfig`, `StoredProfile`,
`StoredVariant` (+`RowVariant` alias), `EntityProfile` **with its inherent
resolve machinery** (V3), `ProfileCache` (+ the new pub API from V4),
`CompiledComputedField`, trait `ProfileResolving` (returns `RenderProfile`).
Stays in holon::entity_profile: `ParsedProfile` + parsing free fns,
`ProfileResolver`, `LiveEntities`, `register_entity_lookups`,
`storage_entity_to_rhai_map`, `UI_STATE_VARIABLES` (move only if the resolve
machinery needs it — check at implementation). holon::entity_profile
re-exports the moved items; `type_registry.rs:22` alias retargets.

### Step 4 — small type relocations
- `PublishErrorTracker` (holon/src/sync/event_bus.rs:23, atomics-only) →
  holon-core. Retarget all users; no compat shim.
- `StorageSelector` (holon/src/di/lifecycle.rs:24, serde+Default config enum)
  → holon-api. Retarget `holon::di::StorageSelector` users (config.rs:67,
  holon-app, holon DI internals).

### Step 5 — BlockCellRegistry seam
`ReactiveEngine.block_cell_registry`:
`Mutex<Option<Arc<BlockCellRegistry>>>` →
`Mutex<Option<Arc<dyn holon_core::cell::EntityCellRegistry>>>`.
sut.rs:838 coerces its concrete Arc at the call site.
