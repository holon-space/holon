## F2 Step 1b — Full structural transition set (Join + Split)

Extended the memory-slice transition harness from reparent/reorder ops to the **complete six-transition set** by adding JoinBlock and SplitBlock, both driven through the production `SutBlockTreeWrite` cap + `ReferenceState` oracle + proptest-state-machine.

**What happened:**

- Implemented `apply_join_block`: seeded `navigation_history` to activate Join's generator; reparent children *before* delete to avoid cascade issues in MemoryBackend.
- Proptest uncovered a **real order-parity bug** — sibling order drifts between SUT (raw vec) and ref (re-canonicalized by `(content_group, sequence, id)` on every move). Fixed with `resync_sibling_order`, a guarded reorder that only touches parents whose child *set* already matches the ref, preventing false masking of parent/content bugs.
- Implemented `apply_split_with_id` with **stateless id-reconciliation**: the ref mints `:split-N` (leading-colon path that breaks `MemoryBackend::from_raw`); normalize to bare `split-N` at the dispatcher boundary and in ref projection via `project_ref_blocks` helper.
- Proptest found a second bug: dispatcher must normalize *incoming* ref ids before calling SUT methods. Fixed by moving normalization into the dispatcher itself.

**Challenges:**

- **`move_block` semantics mismatch**: `None` means append-to-END in MemoryBackend but insert-at-FRONT in ReferenceState. Reframed MoveUp as "swap with previous sibling" to avoid `None` entirely.
- **Join vacuity**: generator keyed on `current_focus` (navigation_history), which isn't seeded by default. Seeded it in bootstrap so Join fires from the start.
- **Split id format**: `:split-N` paths break the MemoryBackend round-trip; stripped the colon statelessly in normalization.

**Status:** Full structural set (Indent/Outdent/MoveUp/MoveDown/Join/Split) green over real MemoryBackend — 1500-case proptest, teeth-verified, archlint clean, zero warnings. Next: apply same pattern to `loro_slice` and `sql_slice`.
