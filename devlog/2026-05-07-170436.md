## Turso IVM Bug Investigation — Live Geometry Fixes Extended

**Context**
The PBT verification sweep uncovered a new panic class: Turso incremental view materialization (IVM) disagreement in the `focus_roots` matview. The `block` matview is dropping rows that exist in the base table, causing downstream assertions to fail.

**What happened**

- Reproduced focus_roots panic at `sut.rs:4002` with `HOLON_TRACE_SQL=1` enabled to capture SQL sequence
- Found that `block_raw` (base table) contained rows missing from the `block` matview after Outdent transitions
- Initial repro showed `block:0a` missing; subsequent runs showed `block:2-mq-o5-o-s03i` missing — pattern suggests transient CDC state, not offline replay bug
- Offline SQL replay (using `turso_sql_replay.rs`) showed the matview consistent when replayed in isolation — indicates the bug is a race condition or mid-transaction state visibility issue in Turso's IVM
- Built diagnostic infrastructure to capture traces:
  - Patched `trace_sql` to emit to stderr via `eprintln!` when `HOLON_TRACE_SQL=1`, bypassing the `release_max_level_info` compile-time filter
  - Extracted SQL sequences from panic logs and began offline replay analysis

**Challenges**

- **Compile-time trace filtering**: `release_max_level_info` in workspace-hack compiled out all `trace!` macros; worked around by adding conditional `eprintln!` in `trace_sql`
- **Transient vs. offline bug distinction**: offline replay showed no inconsistency, but PBT panicked on the same SQL — suggests the bug is a race in Turso's CDC processing mid-transaction, not a logical error in the view definition
- **Count-based consistency checks are insufficient**: initial matview checks only counted rows; the bug manifests as specific IDs present/missing despite matching counts

**Decisions**

- Extended `turso_sql_replay` tool with three diagnostic enhancements:
  1. **EXCEPT-based row-set diff**: replaced count-only checks with `SELECT ... EXCEPT` to detect row-content and row-presence mismatches
  2. **`--track-id` flag**: per-statement row presence trace (which DML statement drops the row) for multi-table chains (block_raw → block → focus_roots)
  3. **`-- ?ASSERT` directives**: parser extension for self-checking repro files (allows shipping SQL repros as minimal bug reports)
- Started with (1)+(2) since they directly unblock the investigation; (3) improves future bug report hygiene

**Status**
Tools enhanced; awaiting fresh trace replay with row-diff and per-statement tracking to pinpoint which Turso CDC operation drops the row and at which step. Next: run PBT with enhanced tool to isolate the precise failing statement.
