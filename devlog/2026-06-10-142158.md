## Major deviations

### Stage 7 — `turso` relocation (lean interpretation)
**Plan said:** Move all Turso usage into holon-app.  
**What I did:** Found only 5 lines of actual `turso::` usage in holon-orgmode (the `DbHandle::execute_values` seam). The remaining ~2000 lines of orgmode impls use `holon::` paths only, so they're archlint-clean where they live. Left them in holon-orgmode to avoid a 2kloc diff churn with zero architectural benefit.  
**Rationale:** True decoupling is about *interfaces*, not crate boundaries. A 100-line trait seam beats a 2000-line module move that touches zero actual storage calls.

### Stage 4 — read-path `BlockQuery` settling (design call)
**Plan said:** Mirror editor's raw SQL with `QueryEngine::block_content_by_id`.  
**What I discovered:** The snapshot path settles CDC (kills pending deltas), which masks the races that PBTs hunt. Kept it non-settling to preserve invariant fidelity.  
**Impact:** Negligible — the only consumer (editor mirror) gets correct, live-updating content.

## Follow-ups & ways to profit from the new architecture

### High-value follow-ups
1. **Stage 10 stretch (in plan):** Relocate `Entity`/`Link` traits to holon-api, breaking the `holon-frontend → holon → {loro,turso}` dep chain entirely. This unblocks:
   - holon-app → holon-api (tiny, no storage)
   - holon-app → {loro, turso} (assembly only)
   - holon-frontend → holon-api only (pure logic)
   - **Benefit:** holon-frontend becomes 100% storage-agnostic; you can swap Loro↔Turso at runtime or build multiple frontends against different backends.

2. **Query precompilation:** `compile_query` is now a `QueryEngine` method; you can build a query cache keyed by `(parsed_ast, lang)` to avoid re-parsing identical live queries in rapid succession. The PBT watcher-collision bug we fixed suggests this happens in the wild.

3. **Link-candidate filtering push-down:** `search_link_candidates(filter) → Vec<LinkCandidate>` is typed now, but the filter is still a generic struct. Pushing filter logic into `QueryEngine` (e.g., `search_links_by_type(entity_id, LinkType::Ref)`) would let Turso do index-accelerated filtering instead of filtering results in-app.
