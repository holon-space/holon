## Fixing IVM LEFT JOIN multi-level aggregation and FILTER clause support

The recent `json_group_array` and `LEFT JOIN` IVM implementation had three gaps: dual-LEFT-JOIN queries silently dropped rows, `FILTER (WHERE ...)` was incorrectly rejected for all DISTINCT aggregates, and correlated subqueries weren't supported. The holon block hydration use case hit the first blocker.

**What happened:**

- Diagnosed root cause of dual-LEFT-JOIN row loss: `execute_node` recursed into shared subtrees twice per row, causing `match_counter` state writes to be observed by downstream operators, producing inconsistent deltas. Rows with no matches in either join branch disappeared silently.
- Implemented per-circuit-run memoization of `execute_node` outputs (`DbspCircuit::exec_node_cache`), cleared at public entry points and between recursive-CTE iterations, fixing the diamond DAG corruption.
- Narrowed the `FILTER + DISTINCT` rejection: only `Count`/`Min`/`Max` and non-distinct-aware aggregates like `Count/Sum/Avg DISTINCT` are blocked; `JsonGroupArray` and `GroupConcat` already gate on `filter_passes` in `apply_delta`.
- Improved error message for unsupported correlated subqueries in matview SELECTs, directing users to the dual-LEFT-JOIN workaround (now unblocked by G0 fix).
- Fixed pre-existing test build error in `operator.rs` test helper: missing `.unwrap()` after `to_values` API changed to return `Result`.

**Challenges:**

- **Multi-rev distribution**: G0 fix (memoization) belonged on the LEFT JOIN rev; G1 fix (FILTER narrowing) on the FILTER rev. Used `jj edit` to cleanly separate G0 fixes into the ancestor rev, with auto-rebase handling descendant rebasing.
- **Recursive operator cache invalidation**: Cache leaked results across iterations of recursive CTEs until cleared before each iteration.

**Decisions:**

- Left G2 (correlated subquery decorrelation) unimplemented — it's a new compiler feature beyond "enhance existing revs," and G0 already unblocks the holon use case via equivalent dual-LEFT-JOIN form.

**Status:** G0 and G1 fixed and tested (47 sqltests, 69 IVM integration tests, 187 incremental unit tests passing). Holon block hydration repro now shows correct results. G2 has improved error messaging with workaround guidance.
