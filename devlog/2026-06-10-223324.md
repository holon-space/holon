## Reactive Settle Detection for `gpui_ui_pbt` Performance

**Context:**
The `gpui_ui_pbt` property test harness was 1.38× slower than the headless `general_e2e_pbt` baseline per transition (340ms vs 246ms), with the SplitBlock pipeline hitting 1.64×. The bottleneck was polling loops and fixed sleeps waiting for UI state to settle.

**What happened:**

- Instrumented per-transition timing in both harnesses to identify the settle bottleneck (polling and 15–30ms driver sleeps)
- Implemented `GeometryProvider::changed()` — a `tokio::sync::Notify` fired on every `BoundsRegistry` render commit — replacing 10–50ms geometry polls with reactive notification
- Converted focus-wait loops to use the `focused_block` futures-signal stream instead of polling
- Added window-focus observability via `ElementInfo.focused` per committed frame, then structurally gated keystroke ops on window focus matching the engine's focused editor
- Strengthened the driver interaction pump to force `window.refresh()` per synthetic input, ensuring frames commit even when occluded
- Removed all remaining fixed sleeps (only intentional fallback sleeps remain; documented)

**Challenges:**

- **Stale editor keystroke consumption:** The engine's focused block changes synchronously, but window focus lags one frame. This caused keystroke #2 after a join to be silently consumed by the not-yet-unmounted old editor. Solved by gating every keystroke on `(window_focused_editor == engine.focused_block)` checked post-settle.
- **Byte vs. character column confusion:** GPUI's `check_triggers` callback received character columns but was slicing by byte offsets (the headless path passes bytes). This crashed on multibyte characters in the link and slash trigger pipelines. Fixed the boundary by making the byte contract explicit and converting GPUI's character column to bytes at the harness edge.
- **Ref-model coverage gaps:** Chord operations (Indent, Outdent, MoveUp, MoveDown) didn't model their internal dispatch click, causing spurious off-signature failures. Extended the ref model to record the click side-effect for all four.
- **Build cache exhaustion:** Disk full during dependency compilation; recovered by deleting regenerable artifacts from untouched worktrees.

**Decisions:**

- Used frame-commit notification rather than manual polling: simpler, reactive, and orders of magnitude faster than the previous 10–50ms polls.
- Placed the window-focus gate at the keystroke boundary (not the editor-state boundary): this catches desync early and provides a strong structural invariant for future focus races.
- Documented pre-existing bugs (org-render divergence after Indent, whitespace-only block painting timeouts) rather than blocking on them, to unblock the perf goal.

**Status:**
Goal met: `gpui_ui_pbt` per-transition cost reduced to ~1.26× headless (310ms vs 246ms observed), with SplitBlock apply latency halved (421ms → ~230ms). All validation suites (SqlOnly ×4, Full ×2, headless gate) pass. Two production multibyte-handling crashes in the trigger pipeline now fixed. All changes committed in worktree `gpui-pbt-speed` (jj change `rswxswny`).
