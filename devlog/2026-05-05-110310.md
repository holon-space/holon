# #14: keybindings.yaml moved + send_leader_chord dynamic key lookup (2026-05-05)

Closes task #14. Continues from `devlog/2026-05-05-110308.md`.

## Why

The TUI shortcut-removal Phase A landed `send_leader_chord(key, label)`
with hardcoded `"h"`/`"b"`/`"f"` at the 3 nav call sites. If the YAML
moves a binding (e.g. `h` → `g` for go_home), the test would silently
keep sending the wrong key. Per user request: read keys dynamically
from the YAML.

Bundled with the move of the binding source to a shared canonical
location (`assets/default/`).

## What landed

### Move

`frontends/tui/config/keybindings.yaml` → `assets/default/keybindings.yaml`

`frontends/tui/config/` directory removed (it had only that one file).
This brings keybindings into the same `assets/default/` tree as
`index.org`, the Journals/Notes seeds, and `types/*.yaml` —
the canonical seed-and-config tree.

### include_str! path updates

### serde_yaml-based parser

`crates/holon-integration-tests/src/pbt/sut.rs::leader_key_for(nav_op)`:

```rust
fn leader_key_for(nav_op: &str) -> &'static str {
    const YAML: &str = include_str!("../../../../assets/default/keybindings.yaml");
    static PARSED: std::sync::OnceLock<KeybindingsFile> = std::sync::OnceLock::new();
    let parsed = PARSED.get_or_init(|| {
        serde_yaml::from_str(YAML).expect("assets/default/keybindings.yaml must parse")
    });
    parsed.bindings.iter().find_map(|b| {
        if b.context == "navigation"
            && b.action == nav_op
            && b.modifiers.iter().any(|m| m == "leader")
        { Some(b.key.as_str()) } else { None }
    }).unwrap_or_else(|| panic!(...))
}

#[derive(serde::Deserialize)]
struct KeybindingsFile { bindings: Vec<KeybindingEntry> }

#[derive(serde::Deserialize)]
struct KeybindingEntry {
    key: String,
    #[serde(default)] modifiers: Vec<String>,
    context: String,
    action: String,
}
```

Replaces the ~50-line custom line-walker. `serde_yaml` added as
optional dep gated on the `pbt` feature
(`crates/holon-integration-tests/Cargo.toml`).

`yaml_leader_bindings_resolve_to_expected_keys` asserts h/b/f resolve
for go_home/go_back/go_forward — the binding-source contract.
`unknown_nav_op_panics` asserts unknown ops panic with a useful
message. `direct_non_leader_binding_does_not_match` asserts that a
direct (non-leader) binding like `switch_region` (Tab) is correctly
filtered out — so a future caller mis-wiring `switch_region` as a
leader chord would fail loudly at startup.
