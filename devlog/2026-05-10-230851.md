## Researched AOP Patterns in Rust and Strategic Debug Instrumentation

**Context:** Investigated how to inject debug logging (`eprintln!`) at strategic code positions without manual instrumentation, exploring Aspect-Oriented Programming patterns available in Rust.

**What happened:**

- Researched native AOP support in Rust and found that Rust doesn't have built-in AOP like Java's AspectJ, but provides equivalent patterns through macros and traits
- Identified three main approaches for injecting `eprintln!` at strategic positions:
  - **Procedural macros** — custom attribute macros for fine-grained function-level instrumentation
  - **`tracing` crate** — idiomatic Rust approach with environment variable filtering via `RUST_LOG`
  - **ast-grep** — bulk AST-based code injection across multiple files
- Provided working examples of procedural macro structure using `syn` and `quote!` for wrapping functions with entry/exit logging
- Explained why Rust's design makes traditional AOP less necessary — traits, macros, and generics handle most cross-cutting concerns more ergonomically

**Decisions:**

- Recommended `tracing` crate as the standard Rust approach for general instrumentation, with `RUST_LOG` environment variable filtering for runtime control
- Suggested procedural macros for cases requiring fine-grained selective instrumentation on specific functions

**Status:** Research phase complete with practical recommendations delivered. No code implementation attempted pending clarification of specific use case (module debugging, performance profiling, or general instrumentation).
