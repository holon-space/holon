## Fixed squash-frontends.sh shebang and grep anchor bug

The `squash-frontends.sh` script was failing silently on two directories and had a syntax error preventing execution altogether.

**What happened**

- Script failed to run with "syntax error near unexpected token `<`" — the shebang was on line 2 instead of line 1, causing the kernel to invoke `/bin/sh` instead of `bash`, which doesn't support process substitution `< <(...)`
- Moved shebang to line 1, script executed successfully
- Discovered two directories were falsely skipped despite having changes: `frontends/gpui` (30 files) and `frontends/waterui` (10 files)
- Root cause: line 40 used unanchored `grep "0 files changed"`, which matched any file count *ending* in `0` (10, 20, 30…)
- Fixed by anchoring the grep: `grep -qE "^0 files changed"`
- Re-ran script to squash the missed directories

**Status**

Script now correctly squashes all directories with pending changes. Only root-level files and untracked directories remain in working copy — these lack matching bookmarks and are outside the script's design scope.
