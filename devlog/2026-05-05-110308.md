## New holon regression surfaced: NavigateHome on headless drivers

With the Turso panic gone, the next failure was deterministic:

```
[NavigateHome] leader-space keystroke failed:
  send_raw_keystroke is unimplemented for this UserDriver.
  Atomic editor primitives need a real-input driver (GpuiUserDriver).
  Was PBT_ATOMIC_EDITOR=1 set in a headless run?
```

`apply_navigate_home`/`Back`/`Forward` route through
`SUT::send_leader_chord(key, label)` which always called
`UserDriver::send_raw_keystroke`. Default `send_raw_keystroke` impl
errors out — only `TuiUserDriver` implements it. **All PBT variants
(Full, SqlOnly, CrossExecutor) install `ReactiveEngineDriver`** at
`sut.rs:2545`, so the chord path always failed.

This was a regression from the TUI shortcut removal in
`devlog/2026-05-05-handoff-tui-pbt.md` Phase A: the SUT used to call
`engine.execute_op("navigation", ...)` for the headless variants.
That was removed without a replacement.

## Fix: synthetic_dispatch fallback

`SUT::send_leader_chord` now signature `(key, nav_op, label)`. It
tries `send_raw_keystroke` first (TUI native driver). On error, falls
back to `synthetic_dispatch("navigation", nav_op, {region: "main"})`
— **the same intent the TUI's `dispatch_navigation_op` runs after the
chord matches** (`frontends/tui/src/app_main.rs:714`).

Three call sites updated:
- `apply_navigate_back`  → `("b", "go_back",    "NavigateBack")`
- `apply_navigate_forward`→ `("f", "go_forward", "NavigateForward")`
- `apply_navigate_home`  → `("h", "go_home",    "NavigateHome")`

This preserves the real-input path for the (eventual) TuiUserDriver
PBT runs while letting headless variants exercise the same operation.
