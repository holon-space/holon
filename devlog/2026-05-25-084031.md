## Fixed TriggerSlashCommand precondition gate in SqlOnly PBT

The `general_e2e_pbt_sql_only` diagnostic was halting on `TriggerSlashCommand` with a misleading "Loro tree not ready" error. Investigation revealed the real issue: this transition was the only char-typing operation missing an `enable_loro` precondition gate.

### What happened

- **Ran diagnostic** on all 6 remaining handoff issues with invariants in `warn` mode to surface live failures.
- **Found #3 blocking early:** `TriggerSlashCommand` panicked at 49.93s, claiming the Loro `content_raw` text container "isn't resolvable yet."
- **Traced root cause:** SqlOnly has no Loro provider, so `editable_text()` always returns `Err`. The five sibling char-typing transitions (`TypeChars`, `DeleteBackward`, `MoveCursor`, `PressKey`, `FocusEditableText`) all gate on `check(state.enable_loro(), …)`, but `TriggerSlashCommand::preconditions` lacked this gate, causing it to generate and self-destruct in SqlOnly mode.
- **Applied one-line fix:** Added `state.variant.enable_loro` gate to `TriggerSlashCommand::preconditions` (matching sibling pattern in `press_key.rs`, `move_cursor.rs`, etc.).
- **Verified:** Re-ran diagnostic, confirming zero `TriggerSlashCommand` panics and no "did not dispatch" failures across 600s of exploration.
- **Confirmation run:** 10-case Strict run (all invariants except matview) completed green in 178s, confirming **5 of 6 handoff issues resolved**: #1 (vfn), #2 (Indent chord), #3 (slash command), #4 (blocks-match-ref), #6 (org-render-fixed-point).

### Challenges

**Misleading error message:** The headless mirror's "hasn't landed in the Loro tree" error masked the real issue — in SqlOnly there's no Loro tree at all. Initial handoff hypothesis ("increase settle timeout") was misdirected.

**Trait method vs. field:** First attempt used `state.enable_loro()` (trait method), but the file had no scope for `RefLifecycle`. Resolved by using the field directly (`state.variant.enable_loro`), matching the sibling transitions' actual pattern.

### Status

Five issues confirmed resolved; #5 (`inv-matview-consistent-with-ref`) isolated as the sole remaining item — it's an invariant-design artifact (comparing hierarchy levels) with real under-projection already covered by Strict siblings.
