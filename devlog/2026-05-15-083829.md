## Senior Review & Implementation: GitHub MCP FK Enumeration (Paired Bindings)

**Context**: The plan for GitHub issue/PR enumeration was thin on the hard requirements. Ran a critical review against the source code, then implemented Phase 2 (the structural machinery in `mcp_vtable.rs`).

**What happened**:
- Conducted a "I hate this plan" senior review against live source, uncovering 11 design gaps: tuple-field mapping was underspecified, pagination ignored, credential storage unvetted, `write_through` semantics misread, array-into-TEXT behavior unverified, and `EnumerateFrom` migration path missing.
- Identified cheap hypothesis validations (H4: loader dir-driven ✓; H7: `write_through` is cache-population ✓) and gated expensive ones (H1–H3, H5–H6) on a live MCP probe (Phase 0).
- Renamed `fallback` → `enumeration` throughout to satisfy archlint word-smell and match the concept (FK enumeration source, not failure-mode fallback).
- Implemented paired-binding support: `EnumerateFrom` now handles both legacy `field: id` (back-compat) and new `fields: { tool_param: parent_column }` for correlated FKs like `(owner, repo)`.
- Added `enumerate_from: Option<EnumerateFrom>` to `FilterColumnConfig`; `FetchMode::Tool` gained `enumerations: HashMap<String, ResolvedEnumeration>`.
- Refactored `McpCursor::filter()` Tool branch to mirror URI branch logic with shared fan-out helpers (`pick_unresolved_enumerations_*`, `run_enumeration`).
- `run_enumeration` now returns `Vec<HashMap<String, String>>` (one binding-map per parent row) instead of `Vec<String>`, enabling paired bindings.
- `build_fdw_metadata` forces params bound by any enumeration to non-required, overriding YAML `required: true`.
- Added explicit invariant: max one independent enumeration per fetch (correlated FKs use paired `fields:`; Cartesian product rejected).

**Challenges**:
- **Factual vs. design errors**: Plan cited wrong line numbers (`McpForeignDataWrapper::new` L281–319 vs. actual L268–351) and misattributed `FilterColumnConfig` location. Re-reading source was essential before code.
- **Underspecified tuple mapping**: `fields: [owner, name]` → `[owner, repo]` param binding was positional, not explicit. Fixed by requiring paired shape `{ owner: owner, repo: name }` with direction spelled out.
- **Breaking return-type change**: `enumerate_fallback_values` → `run_enumeration` returning HashMap instead of String broke the URI branch call site. Added a `pick_unresolved_*` adapter for the single-field case.

**Decisions**:
- **`#[serde(untagged)]` for `EnumerateFrom`** — preserves back-compat with singular `field:` in existing `claude-history.yaml`, avoiding a migration burden.
- **Reject multi-independent enumerations** — GitHub's use case (correlated `owner`+`repo`) is inherently paired. Cartesian-product fan-out is wrong and expensive; one enumeration per fetch
