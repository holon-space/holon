## Adversarial Code Review: Harmonic Thimble PBT Plan

**Context**: A plan to integrate GPUI input into a TUI property-based test harness was reviewed with a critical eye to uncover load-bearing bugs, lost-wakeup races, and fragile assumptions before implementation.

**What happened**

- Read the original plan and validated its 12 key hypotheses against `app_main.rs`, `tui_ui_pbt.rs`, and `user_driver.rs`
- Discovered three blocking correctness bugs: (1) fire-and-forget engine dispatch creates a spawn-vs-render race where assertions observe stale state; (2) `Notify::notified()` without `enable()` loses wakeups between interest creation and first poll; (3) chord translation conflates GPUI and TUI keymaps instead of dispatching on resolved operation names
- Identified seven secondary issues: `AppMain::default()` per-input is unnecessary churn (reuse existing `CapturingApp`), periodic timer is 100 ms not 200 ms, `type_text` silently degrades on focus loss, `nav_to` lacks bounds checks on registry churn, timer arm starves input in `select!`, `edit_mode` doesn't force re-renders on all events, and edit-mode structural ops (split/join) are unaddressed
- Rewrote the plan to fix all three blockers: added `await_chord_settled` (render → engine quiesce → render) gated on a new task, replaced `Notify::notified()` with `pin!().enable()`, replaced chord-character translation with semantic dispatch via `bubble_input_oneshot`
- Added four verification tasks: confirm `wait_for_quiesce` exists or build a fallback, enumerate actual PBT generator chords, run 50× stability test to flush spawn/render races, defer Ctrl+x split/join to follow-up

**Challenges**

- The fire-and-forget dispatch was not obvious from the input path — required tracing `dispatch_block_op_on_focused` through `tokio::spawn` calls in `app_main.rs:681`
- Lost-wakeup race is a textbook tokio footgun; plan mentioned `Notify` but not the `enable()` barrier, caught by reading tokio docs against the proposed code structure
- Chord translation as character rewriting conflates two key-namespaces; solved by reusing the existing `bubble_input_oneshot` primitive that already resolves GPUI chords to operation names

**Status**: Plan rewritten with three critical bugs fixed, seven secondary issues addressed, and four new verification tasks added. Ready for implementation with higher confidence in correctness and race-condition coverage.
