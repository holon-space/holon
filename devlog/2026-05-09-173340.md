## Senior Review of Block Cell Architecture Plan

The `/senior-review` skill was invoked to critique the "snappy-pnueli" plan with deep skepticism, validating assumptions against actual code and surfacing hidden risks before implementation.

**What happened:**

- Validated six key hypotheses by tracing through production code (`BlockOperations` trait, `ReactiveViewModel` internals, `MemStore` test implementations, `CellRegistryDispatcher` usage patterns)
- Identified that Phase 3's `expanded` field migration **reintroduces the same-id-collision failure** that was deliberately fixed in the FU-1 commit—moving from per-ViewModel `Mutable<bool>` back to a `(uri, field)`-keyed cache
- Found that `cells()` trait default panicking breaks all synthetic test stores (`MemStore` in block_operations_tests.rs); changed to return `Option::None` instead
- Discovered downcast from `dyn CellBacking<String>` to `dyn TextCellBacking` is impossible in Rust without unstable upcast—added explicit `as_text_backing()` accessor pattern
- Flagged cell lifetime risk: cached `Cell<String>` for a deleted block holds orphaned Loro container; added `on_entity_deleted(uri)` invalidation hook requirement
- Replaced Phase 3's three in-memory-state targets with single authority-backed target (`block.completed`) to validate the full cell-write → CDC → signal loop

**Challenges:**

- H2 required walking through FU-1 commit history to recognize the pattern reintroduction
- H5's lifetime issue only surfaced when tracing delete paths through chord ops and `join_block` logic
- Balancing "keep trait defaults for test substrate" vs. "make defaults safe"—solved by returning `None` rather than panicking

**Decisions:**

- Deferred `CellRegistryDispatcher` to F5 (YAGNI with only one impl today); Phase 1 uses `BlockCellRegistry` directly
- Shifted Phase 3 validation strategy from three in-memory fields to one SQL-backed field with real CDC writer

**Status:** Plan patched with six concrete fixes, three advisory concerns (C1–C3), and two new open questions (Q7–Q8) added for reviewer; ready for implementation checkpoint.
