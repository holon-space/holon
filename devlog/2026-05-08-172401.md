## IVM Transaction State Rollback Fix & Phase 2 Investigation

### Context
Continuing the IVM fuzzer followup work from the handoff document. Phase 1 addressed a matview drift bug after failed UPDATEs; Phase 2 investigates aggregate matview duplicate-dropping.

### What happened

**Phase 1 — Complete**
- Reproduced and fixed the `confident_eloff` matview drift bug (rows disappearing after failed UPDATE)
- Root cause: `view_transaction_states` never rolled back when statements aborted, leaving stale deltas that corrupted matviews on next read
- Implemented fix across 3 files (~75 LOC): snapshot/rollback logic in `ViewTransactionState`, wired into `begin_statement` and `end_statement` in `ProgramState`
- Added integration tests; verified all 9 pre-existing `ivm-rollback.sqltest` cases now pass
- Confirmed 74 existing IVM tests still pass; original fuzzer seed `12371730315876910877` no longer fails

**Phase 2 — Partial**
- Attempted to reproduce the handoff's "aggregate matview drops 12-of-same row to 1" pattern across 500+ fuzzer seeds
- Could not find a clean aggregate-specific repro; instead discovered a **LEFT JOIN multiplicity bug** (seed 344, matview `honest_editions`): Turso returns 23 rows vs SQLite's 340
- Traced likely root cause to `MatchCounterOperator` per-entry accounting when a single δL key matches many δR entries with identical keys
- Bug requires intermediate CTAS table + preceding matviews; simple 1×N LEFT JOIN reproducer works correctly

### Challenges

- **Phase 2 minimization slow**: The LEFT JOIN bug doesn't trigger in isolation; requires a specific matview chain context, making bisection difficult without understanding the full circuit
- **Seed-based vs pattern-based**: Handoff described an aggregate pattern, but fuzzer seed 344 is a LEFT JOIN issue — unclear if these are the same bug or if Phase 2 is in a different seed range

### Decisions

- **Document and hand off Phase 2**: Rather than speculate on root cause without a minimal repro, created `HANDOFF_phase2_left_join_multiplicity_2026-05-08.md` with seed-based reproducer, minimization strategies, and RCA pointers into `match_counter_operator.rs`
- **Phase 1 ships clean**: Rollback fix is solid, tests comprehensive, no regressions

### Status

Phase 1 fixed and verified. Phase 2 identified but not minimized — LEFT JOIN multiplicity bug in seed 344 requires further reduction or direct RCA. Phases 3–5 remain untouched. Ready to either (a) deep-dive Phase 2 RCA, (b) jump to Phase 3 (SUM/AVG divergence), or (c) wrap and document.
