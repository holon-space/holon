## Antijoin Operator Rewrite: MatchCounter → Antijoin

**Context**  
The LEFT JOIN implementation had four bugs rooted in a complex two-phase state machine (Phases B & C) with unspecified ordering hazards and redundant state reads. A senior-dev review exposed factual errors in the rewrite plan, an ordering bug in the delta formula, and non-existent subsystems the plan assumed. The single-user constraint eliminated the need for a format-version migration mechanism.

**What happened**

- **H1 validation (critical gate)**: Traced the chained-matview eval bug through Phase B's `read_l_presence` call; antijoin removes the L-pass staleness path entirely but R-pass still scans `L_INDEX` btree, so the bug persists only if read-your-writes is broken at the cascade boundary (acceptable risk).
- **Strategic pivot**: Renamed `MatchCounterOperator` → `AntijoinOperator` in-place rather than rewriting from scratch. Kept storage layout (`L_INDEX`, `R_COUNT`) and I/O discipline (`sought:bool` per yield).
- **Fixed Phase C formula**: Now emits `δL · [c_post==0]` directly instead of the hand-wavy "exclude δL rows" logic. Eliminates the `L_PRESENCE` read on the L-pass and removes the `delta_l_rows` exclusion in Phase B — R-pass and L-pass now partition cleanly.
- **Wired up compiler**: Replaced `EvalState::MatchCounter` and `DbspOperator::MatchCounter` variants; updated all doc comments and module exports.
- **Test validation**: 18/18 LEFT JOIN ivm tests, 76/76 integration tests, 2062/2062 sqltests (pre-existing tokio overflow stopped the run). Fuzzer confirmed antijoin gets past the stmt 523 LEFT JOIN failure point on main and trips instead on a separate aggregate-matview bug — evidence the LEFT JOIN bug class is fixed.

**Challenges**

- **Formula ordering hazard**: The original plan's "exclude δL rows from the scan" was mathematically wrong for mixed insert-retract cases at the same key. The fix required explicit ordering: R-deltas against `L_pre` first, then L-deltas against `L_post` after `R_COUNT` persistence. This became load-bearing for correctness.
- **Pre-existing compile errors**: Fixed `translator.rs` missing `Table::RecursiveCte` arm and `property.rs` missing `conflict: None` in `Insert::Values` before the antijoin rewrite could compile.
- **Worktree symlink conflict**: Initial attempt to create the worktree hit a `.git` symlink issue; resolved by adjusting the branch setup.

**Decisions**

- **No format-version subsystem**: Dropped entirely since you're the only consumer and can drop the DB. Commit message will note "rebuild any LEFT-JOIN matview after upgrade" and trust the user to handle it.
- **In-place rename over from-scratch rewrite**: Minimized risk by keeping the proven storage and I/O structure; only the Phase C emit logic changed. Faster, lower surface area for bugs.

Implementation complete and committed to `antijoin-rewrite` branch. All LEFT JOIN tests pass; fuzzer evidence shows the rewrite fixes the stmt 523 LEFT JOIN failure class. Fuzzer
