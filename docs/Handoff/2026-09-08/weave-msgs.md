## guests-repro
build(guests): guest wasm artifacts build byte-identically from any checkout, so the landing gate's rebuild-and-compare step (just guests-verify) measures source drift and nothing else. Root cause: Cargo hashes a path package's absolute directory into -C metadata, which renames symbols and reorders the LTO output, so two checkouts of identical sources produced different bytes (201-byte divergence with zero leaked path strings); absolute paths also leaked into panic strings. guests/build.sh now stages the sources under a content-addressed directory below HOLON_GUEST_STAGE (default /tmp/holon-guest-build), builds there under an exclusive mkdir lock (concurrent builds of one guest from two workspaces serialise and yield the same bytes) with --locked and --remap-path-prefix for the stage root and CARGO_HOME, sweeping stage dirs older than 14 days, and never runs wasm-opt (previously applied only when binaryen happened to be on PATH — a gate must not depend on what is installed). Both tracked artifacts regenerated: two directories yield one sha256; guests-verify matches; plugin-host and kitchen suites incl. the cooklang differential PBT green.

## mcp-authority-fix
fix(connections): a sidecar-mirrored entity the connector does not write no longer panics the app at boot. Booting with any connected sidecar that mirrors an entity it holds no write tool for — no tool at all, or a read-only one — crashed in OperationModule::configure before any UI existed to disclose it: write authority for free-standing type 'fk_fake_shadow': […] declares no properties overflow column. Root cause: the stamp-home requirement (require_engine_stamp_has_a_home) swept the hand-written DDL, the keystone datatype axis and the admission tests onto FieldSchema::overflow_pair(), but not EntityConfig::to_type_definition — the one producer of the type every mirrored entity is registered under and the mirror table's DDL is generated from. A sidecar's schema: names the columns the connector mirrors, which is a different set from the columns a row needs to be writable, so the derived type had no home for the engine's _provenance stamp; the boot loop skips only types whose connector already holds an authority, so a read-only mirror reached the check and the derived-authority registration panicked. to_type_definition now appends the overflow pair, which puts the two columns in the registry and in the table alike, and leaves a schema that declares properties itself as authored so the type's own value_kind decides. boot_suite 21/21, the four-crate gate 1131/1131 with an empty failure set, keystone-smoke 4/4, fmt clean; holon-mcp-client fully green. Bugfunnel 2026-09-08-sidecar-mirrored-type-has-no-stamp-home-panics-boot (ENVIRONMENT/COVERAGE, FIXED): the covering harness existed and had the right oracle, but no gate compiled the crate that holds it.

## pair-conflict-badge
feat(pairing): show a pairing conflict copy as a badge and disclose how to find them. Pairing a device that was already used solo keeps this device's divergent text as a child of the owner's node, marked with pairing_conflict_of. Nothing rendered that property, so the copy was indistinguishable from a block the user wrote — a merge they could not see. A pairing_conflict variant in the block profile keys on the property and draws a badge beside the row's own text. Block properties already flatten into the Rhai scope on both the SQL and the Loro leg, so the variant needs no new column: an absent property binds nothing and the row falls through. The property is the only mark, because a marked title would be written back into the user's org file. Deleting the property or the block removes it. The variant sits above every other: a conflict copy of a rule head or of a Page-tagged block would otherwise render as its card or its embedded page and wear no mark at all. A variant's render expression is the whole row, so the copy reads as an ordinary row until the user resolves it. A badge whose label is a literal has no row binding, so badge now takes a block_id and records it through BoundsRegistry: what the user reads is attributable to the block it marks. The pairing disclosure counted the conflict copies but gave no way to reach them. conflict_copies_query composes that query from the property name, and the pair_with_owner response carries it.
