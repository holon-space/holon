## 3. The no-pages-under-non-pages constraint (first-class design)

**Ruling (`PageHierarchy-2026-07-13.md`):** a page's structural ancestors, walking to a
root, must all be pages — else the ancestor is the root itself. Pages under non-pages are
prohibited for now.

**Where it bites:** `DocumentManager::name_chain` (`sync_ports.rs:169-190`) walks
`parent_id` to root and does `if doc.is_page() { chain.push(doc.title()) }` — it **silently
drops** any non-page ancestor from the path. Consequences of the silent skip:
- It is a silent coercion (contra CLAUDE.md "parse, don't validate" / "fail loud"): a
  prohibited topology yields a *plausible-looking* path instead of an error.
- It is a latent **path-collision generator**: `A(page) > b1 > P` and `A(page) > b2 > P`
  both collapse to `A/P.org` → one overwrites the other (silent loss — R5/R8).

**Decision: (a) fail loud at `name_chain`.** Replace the silent skip with an assertion: an
ancestor between a page and its nearest page/root ancestor that is **not** a page is a
`bail!`/`ensure!` error carrying the offending block id, the page id, and the parent chain.
Do **not** reparent, coerce, or slug around it.

**Why (a) and not (b) "assume some layer enforces it":** verification shows **no layer
enforces it today.** Fork A only makes the `Page` tag *truthful*; it does not constrain a
page's parent to be a page. `seed.rs` has a *precedent* assertion but only for the **seed
set** (`seed_routing_doc`, `seed.rs:188-197,237`: "seed block has no Page ancestor" panics)
— it does not cover runtime rule-created or ingested topologies. So "assume enforced
elsewhere" would be assuming a guarantee nobody provides. `name_chain` is the single choke
point (one caller: `doc_id_to_path`, `file_sync_controller.rs:3168`), so the assertion is
cheap and total.

**Placement precision:** assert in `name_chain` itself (the invariant is about the chain it
walks), mirroring the existing `seed_routing_doc` phrasing so the two read as one rule. The
sweep (`materialize_missing_page_files`) and `doc_id_to_path` inherit the failure loudly.

### 3.1 SENIOR REVIEW (2026-07-13) — verified against this workspace @ `mumrxunz f745553f`

Three concrete, code-verified corrections to §3 before it's safe to implement. Checked with

**FINDING A (blocking, must fix in B1 or the assertion is theater).** `name_chain` has
exactly one caller, `doc_id_to_path` (`file_sync_controller.rs:3159-3175`) — confirmed, the
07-12/§3 "cheap and total" framing is right about *reach* but wrong about *effect*:
```rust
match self.doc_manager.name_chain(doc_id).await {
    Ok(chain) if !chain.is_empty() => Some(...),
    Ok(_) => None,
    Err(_) => None,   // <-- swallows the new fail-loud Err into the SAME bucket as
}                      //     "legitimately not a page" — CLAUDE.md "NEVER swallow errors"
```
`doc_id_to_path` has three callers, and every one already treats `None` as a silent,
unlogged skip:
- `on_block_changed` (`:2110`) → `None => return Ok(false)` — a live user edit to a
  prohibited-topology page **silently never writes to disk**. No error, no log line. This
  is a *regression*: today (no prohibition enforced) that edit writes fine; after B1 it
  vanishes silently. That is the opposite of "fail loud."
- `materialize_missing_page_files` (`:2744`) → `None => continue` — the boot sweep silently
  skips the offending page forever.
- `writeback_sibling_grounding` (`:3063`) → `None => continue` — a de-inlined sibling that
  hits the new assertion is silently treated as "no sibling home," which **defeats the
  guard**: the block now looks ungrounded and the mass-truncation tripwire may fire on an
  unrelated companion write.
**Required fix, part of B1, not optional:** change `doc_id_to_path`'s return type (or add a
sibling method) to distinguish `Ok(None)` (legitimately not a page / empty chain — today's
behavior, keep silent) from `Err` (name_chain's new assertion — a real, previously-unseen
condition). Propagate the `Err` to all three call sites and `tracing::error!` there
(consistent with the `pbt-no-swallowed-errors` invariant — ERROR events are watched by the
keystone) with the offending doc id, non-page ancestor id, and full chain so far. Decide
bounded blast radius explicitly per call site (crash-the-whole-sync-loop is NOT the answer;
"log loud + skip this one document" is), and say so in the plan rather than leaving it
implicit. This is now the load-bearing part of §3 — without it, the fail-loud assertion
degrades to a silent no-op identical to today's silent skip, just with extra branches.

**FINDING B (implementation precision).** The existing loop conflates "self" (iteration 1 —
`current_id == doc_id`, the page whose chain we're building) with "ancestor" (iteration 2+ —
the actual scope of the new rule) under one uniform `if doc.is_page() { push }` check. The
prose "an ancestor between a page and its nearest page/root ancestor that is not a page" does
not by itself tell an implementer which loop iteration to start asserting on. Concrete
guidance for the executor:
```rust
let mut is_self = true;
loop {
    if current_id == EntityUri::no_parent() || current_id.is_sentinel() { break; }
    let doc = self.get_by_id(&current_id).await?.ok_or_else(...)?;
    if doc.is_page() {
        chain.push(doc.title());
    } else if !is_self {
        bail!("name_chain: block {} has non-page ancestor {} (page={})", doc_id, current_id, doc_id);
    }
    // else: doc_id itself not being a page is a separate caller-misuse invariant —
    // decide in B1 whether to also assert here (recommended: yes, same bail, different
    // message) rather than silently producing a chain that omits the page's own title.
    is_self = false;
    current_id = doc.parent_id.clone();
}
```
Also: the root check must match the loop's actual break condition — **both**
`no_parent()` **and** `is_sentinel()` count as a valid root stop (verified,
`entity_uri.rs:117,155` — two distinct predicates, `is_sentinel` is the broader one covering
synthetic ids too). A design that only recognizes `no_parent()` as "root" will false-positive
bail on legitimate sentinel-rooted chains.

**FINDING C (evidence contradiction worth resolving before wiring the keystone, feeds R9).**
`row_origin.rs:243-247`'s comment (written for BugFunnel #67) asserts "`block:journals`...
is not itself a `Page`." This is **directly contradicted** by a standing test:
`holon-frontend/src/lib.rs:806`, `assert!(page.is_page(), "block:journals is the Page
shell")`, with `page.parent_id == EntityUri::no_parent()` (`:807`, unconditional, not behind
a flag). So `block:journals` genuinely IS a Page whose parent is the root — which means B1's
target topology (`journals` → date page) does **not** in fact violate the new no-page-under-
non-page rule (good news, the plan's core design holds) — but the stale/wrong premise in a
comment that governs the exact "disjoint root rows" panic logic R9 is worried about is a
signal that whoever reasoned through that panic fix may have modeled the topology
incorrectly elsewhere in the same function. **Action for the R9 de-risking probe (§4.4/§5.2):
explicitly assert `block:journals.is_page() == true` and `parent_id == no_parent()` as a
precondition check before trusting `resolve_creation_parent`'s multi-root-forest branch
behavior**, and fix or annotate the stale comment once confirmed. Do not treat the comment as
documentation of current behavior.

**Validation performed now (cheap, done during this review):** confirmed via direct grep/read
against this workspace — `doc_id_to_path`'s three call sites and their `None`-handling
(finding A); `EntityUri::no_parent`/`is_sentinel` both exist as distinct predicates (finding
