## Bug

(agent exploration — the untriaged lead the geometry-precision lane surfaced
and deliberately did not chase, from its live run on port 8710 against a
throwaway vault) `BoundsTracker` — a wrapper whose ONLY job is observability
— MUTATES production layout, and the result is that block-row interaction
regions are laid out with zero height while the row's text is displaced to
the right half of the panel. OBSERVED, on the shipped `block_profile.yaml`
main-panel row `row(selectable(draggable(icon)), state_toggle,
rendered_text)` for `block:journals::auto-create`: `selectable` = x356 y50
**420×0**, `draggable` = x356 y50 **420×0** (both `NO-VISIBLE-AREA`),
`rendered_text "Journal Auto-Create"` = **x780** y50 420×6, `drop_zone`
844×4, and the enclosing `column`/`tree_item` therefore only 10px tall. The
sibling `block:__virtual:journals` row — same widget shape, EMPTY text —
gets `selectable` 420×24 and `rendered_text` 420×36, i.e. the placeholder
row is 36px tall while the row that actually has content collapses to 6px.
ROOT CAUSE: `BoundsTracker::request_layout`
(`frontends/gpui/src/geometry.rs:556-570`) builds `gpui::Style::default()` —
which is `display: Display::Block` (verified in the pinned gpui rev,
`crates/gpui/src/style.rs:785`) — and then forces `style.size.width =
gpui::relative(1.0)` and `style.flex_grow = 1.0`. Every `tracked()` widget
therefore requests 100% of its parent's width AND grows. The shipped row has
TWO `tracked()` siblings — `selectable` (`builders/selectable.rs:76`) and
`rendered_text` (`builders/rendered_text.rs:95`); `text.rs:106` and
`editable_text.rs:204` are the other two call sites — so both request 844px
inside an 844px row, flex-shrink resolves them to 420 each (2×420 + gaps =
844, an exact match for the observed numbers), and the block-display wrapper
collapses on the cross axis. THE TREE ALREADY KNOWS:
`frontends/gpui/src/render/builders/live_block.rs:33-37` says verbatim "we
deliberately do NOT wrap in tracked() here. The BoundsTracker's forced style
(width: 100%, flex_grow: 1) is calibrated for small content widgets inside
column-flex lists; wrapping a whole region (row-flex child) causes the
wrapper to collapse to height=0 and clips all region content." That
workaround was applied at that ONE site and the tree was never swept for the
others. NOT A `describe_ui` ARTIFACT — this was the first hypothesis and it
is REFUTED: bounds are recorded in `prepaint`, i.e. AFTER Taffy layout
(`geometry.rs:487-520` for `TransparentTracker`, `:571-605` for
`BoundsTracker`), clipped only by the content mask; all seven nodes of the
row resolve `match=exact` against their OWN `tag_node` trackers with
contiguous sequence numbers `#63`–`#70`, so they come from ONE consistent
pass, and the same dump shows sane rects (32px, 214px rows) for every
sibling. The wrapper does not report early — it CHANGES the layout it is
supposed to only observe. FALSE LEAD, CLOSED so nobody re-chases it: the
`state_toggle` 0×0 in the same dump is BY DESIGN —
`builders/state_toggle.rs:33-35` returns `div().flex_shrink_0()` for a block
with no `task_state`, deliberately collapsing the placeholder to zero width
(dogfood PHASE 3 bug 8). Evidence: raw live capture
`lane-geoprecision/live-describe-ui-{text,json}.json`; re-derived nesting +
geometry at `lane-zhtriage/{tree.txt,tree-text.txt}` (scripts `parse.py`,
`text.py`).
