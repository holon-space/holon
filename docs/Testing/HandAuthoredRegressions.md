# Hand-Authored Keystone Regressions

**Inject a known repro into the keystone PBT directly — without waiting for the
random generator to stumble onto it and minimize it.**

Status: experimental (landed 2026-07-20). Driver:
`crates/holon-integration-tests/tests/hand_authored_regressions.rs`. Sidecar:
`crates/holon-integration-tests/hand-authored-regressions/keystone.jsonl`.

---

## Why the standard regression file can't do this

The keystone (`general_e2e_composed_pbt.rs`) persists failures the normal
proptest way, in
`crates/holon-integration-tests/tests/general_e2e_composed_pbt.proptest-regressions`:

```
cc 7a4d441d1662ab0abf6a9562effb10934b60698788af3c6bf3a506f19498e582 # shrinks to (initial_state, transitions, seen_counter) = (ReferenceState { … } , [ … ], None)
```

The `cc <hex>` token is a **`PersistedSeed(Seed::XorShift(...))`** — a 32-byte
RNG seed (see the pinned proptest fork,
`proptest/src/test_runner/failure_persistence/mod.rs`, and `rng.rs`
`Seed::{to,from}_persistence`). On replay proptest **reseeds its RNG with that
seed and re-runs the whole strategy generation** — `init_state()` +
`transitions()` draws — to reconstruct the case. The `# shrinks to …` text after
the `#` is a human-readable comment; **it is not parsed and not replayed.**

Consequence: a seed regression is **not hand-authorable**. To make the generator
emit a specific `(initial_state, transitions)` you would need the inverse of the
generator — find a seed that happens to draw it. There is no such tool, and even
if there were, any change to a strategy perturbs every seed.

So hand-authoring needs a **different persistence channel** that stores the
concrete case, not a seed. That is what this harness adds.

## What the harness stores instead

The production transition enum
(`crate::pbt::transitions::E2ETransition`, generated by
`declare_e2e_transitions!`) and every variant struct derive
`serde::{Serialize, Deserialize}`. So a **transition sequence is directly
serializable** as JSON.

### The persistence format: one `Fixture<T>`, not a parallel struct

The on-disk/in-memory representation is the canonical **`Fixture<T>`** from
`holon-pbt-core` (`holon_pbt_core::fixture::Fixture`) — the same value-level
regression format the gated PBT slices replay from their `.fixtures/`
directories. There is no bespoke `HandAuthoredCase` struct any more; the driver
aliases `type HandAuthoredCase = Fixture<E2ETransition>` and deserializes each
JSONL line straight into it. A hand-authored case is just a `Fixture` whose
transition type `T = E2ETransition` and whose init type `I` is the default `()`.

`Fixture<T, I>` carries three author-facing fields plus two that hand-authored
cases leave defaulted:

| field | hand-authored use |
|---|---|
| `name: String` | stable slug (printed on run; referenced from `BugFunnel.md` / the fix commit) |
| `description: String` (`#[serde(default)]`) | free-form provenance (the dogfood/report) |
| `transitions: Vec<T>` | the repro, as the production `E2ETransition` enum |
| `environment: CaptureEnvironment` (`#[serde(default)]`) | omitted — the wiring/env-flag capture is for generator-captured fixtures |
| `initial_state: I = ()` (`#[serde(default)]`) | omitted — the base is the fixed `wide_e2e_ref()`, not a serialized `ReferenceState` |

Because the last two are `#[serde(default)]`, a JSONL line that names only
`name`/`description`/`transitions` deserializes losslessly. The sidecar is JSONL
— one `Fixture<E2ETransition>` per line:

```json
{"name": "<slug>", "description": "<provenance>", "transitions": [ <E2ETransition>, … ]}
```

**Upstream convergence.** proptest PR #653 (value-level failure persistence,
unmerged) remains the eventual upstream home for this format per the 2026-06-25
decision; Holon pins upstream proptest v1.10.0 (seed-only) and does **not** touch
that pin. When #653 lands, `Fixture<T>` is the local shape that folds onto it.

Each transition is serde's external-tag form of the enum:

```json
{"CreateBlockUnderFocus": {"content": "Slashy block/", "id": "block:slashy"}}
{"BlockToPage": {"origin_id": "block:slashy"}}
```

`EntityUri` serializes as a plain string (`"block:slashy"`); `id` is
`Option<EntityUri>` (omit or `null` for the mint-when-absent path).

### The one thing that is NOT hand-authored: the initial state

`ReferenceState` derives only `Debug, Clone` — **not** serde (it holds an
`Arc<ShadowInterpreter>`, a Tokio `Runtime`, etc.). Serializing it is neither
practical nor useful. Instead every hand-authored case starts from a **fixed
base oracle**: `wide_e2e_ref()` — the `full_headless` wiring, byte-identical to
running the keystone under `HOLON_PBT_FORCE_FULL=1`. It seeds one focused page
(`block:structural-page`) with three leaf children, over the full Turso +
frontend + org SUT. You express your repro purely as the transition list applied
on top of that base.

If a repro needs a starting shape the base doesn't provide, grow it with
transitions (create blocks, focus, navigate) rather than trying to serialize a
bespoke `ReferenceState`.

## How replay works (same harness as the random keystone)

The driver calls the **exact** keystone entry point:

```rust
ComposedSut::<WideE2E>::test_sequential(config, wide_e2e_ref(), case.transitions, None)
```

`test_sequential` (proptest-state-machine) does, per case:

1. `init_test(&ref_state)` — boot the composed SUT from the base's wiring.
2. `check_invariants` on the initial state.
3. For each transition: `Reference::apply` (the model), then `Self::apply` (the
   production SUT), then the **full composed invariant catalog**.

The only difference from the random keystone is the *source* of
`(initial_state, transitions)` — a fixed base + your list, instead of a proptest
draw. Same SUT, same production transition `apply`, same invariants, same
reporting. Shrinking is irrelevant (the case is already the minimal repro), so
`seen_counter` is `None` and shrink iters are unused.

Parsing is **fail-loud** (parse-don't-validate): an unreadable sidecar, a
malformed line, or an unknown transition variant panics with the offending
`file:line` and the raw line — never a silent skip.

## Authoring procedure: dogfood repro → transition sequence

1. **Reduce the repro to keystone transitions.** Map each user action to an
   `E2ETransition` variant (one per `transitions/<snake_case>.rs`). "Create a
   block and type X" → `CreateBlockUnderFocus{content:"X", id:"block:foo"}`;
   "turn it into a page" → `BlockToPage{origin_id:"block:foo"}`. Pin explicit
   ids (`"id": "block:foo"`) so later transitions can name the same block (the
   born-equal path — oracle and SUT share the id).
2. **Anchor to the base shape.** New blocks land under the single focused page
   (`create_under_focus_parent`). If you need a block under a *page* (e.g. for
   `BlockToPage`, which walks to the nearest page ancestor), the base's focused
   page is already a page — a block created under it qualifies.
3. **Write one JSONL line** with a stable `name` (referenced from the fixing
   commit / `BugFunnel.md`) and a `description` naming the dogfood/report.
4. **Run it** (see below). Confirm it goes RED for the right reason; capture the
   log. It becomes the permanent lock — green once the defect is fixed.

## Running

```
just pbt … # (any keystone gate uses --features pbt)
cargo test -p holon-integration-tests --features pbt \
  --test hand_authored_regressions -- --nocapture 2>&1 | tee /tmp/hand-authored.log
```

Each case prints `[hand-authored regression] running case "<name>"` before it
runs and `PASSED case "<name>"` after — so a red pinpoints the failing line. The
loop stops at the first failing case (fail-loud); put liveness/green cases first.

## Worked example (the shipped sidecar)

`keystone.jsonl` ships two cases:

- **`create-block-smoke`** — a lone clean create. Proves the harness runs green
  cases faithfully (it is not rigged to panic): the full invariant catalog
  engages `2/2` and the case PASSES.
- **`block-to-page-slash-content-empty-segment`** — the dogfood 2026-07-20 bug
  (a1): create a block whose content has a trailing `/`, then convert it to a
  page. Goes RED.

### What the red actually is — and the oracle-gap finding

The red surfaces as a panic at
`crates/holon-integration-tests/src/pbt/transitions/block_to_page.rs:175`:

```
BlockToPage precondition guarantees a legal page-conversion candidate
```

Root cause chain (airtight by code inspection):

- `block_to_page.rs:110` — the model's `plan_new_page` calls
  `PageId::for_path(&full_path).ok()?`, where `full_path =
  "structural-page/Slashy block/"`.
- `holon-api/src/link_parser.rs:158` — `PageId::for_path` splits on `/` and
  **rejects the empty last segment** with the exact production message:
  `page path "…" has an empty segment (leading/trailing or doubled '/'); a page
  path must be non-empty '/'-separated segments` (checked-in test
  `for_path_rejects_empty_segments`, link_parser.rs:576).
- `.ok()? → None` → `apply_to_ref`'s `.expect()` at line 175 panics.

**This is the important finding: the bug is an ORACLE gap, not merely a coverage
gap.** The keystone's reference model *mirrors the buggy planner* — it treats the
origin block's content as a `/`-separated page path via the same
`PageId::for_path`. So the model and production share the identical wrong
assumption, which is exactly why the random keystone never caught this bug: even
if the generator produced slashy content, the model's `candidates()` filter
would gate the transition out (agreeing with the buggy prod), so no divergence
would ever be observed.

The literal production error string was independently captured live in the
dogfood report (headless `execute_operation convert_block_to_page` on content
`"Slashy block/"`): `convert_block_to_page: planning failed: page path
"…/Slashy block/" has an empty segment`. Same `PageId::for_path` defect, one
layer down (the SUT), where the model doesn't gate first.

### The model-first arc for this bug

Per the PBT model-first directive (adapt the model first, red-for-the-right-
reason, then impl to green), the fix flips this case through three states:

1. **Now (model + prod both buggy):** RED at the oracle (`block_to_page.rs:175`)
   — this hand-authored entry. It exposes the shared content-as-path assumption.
2. **Model corrected first** (`page_path_of`/`plan_new_page` treat origin content
   as a single leaf page *name*, not a `/`-split path): the model stops gating,
   `apply_to_ref` proceeds, and the SAME entry now reaches the SUT — going RED at
   the **production planner's** literal "empty segment" error. Red for the right
   reason, one layer down.
3. **Prod corrected** (planner treats content as a leaf too): GREEN. The entry is
   now the permanent regression lock.

A sibling lane owns fix (2)+(3). This entry is the lock that proves it.

## What a hand-authored regression covers — vs. a unit test

Honest assessment (Martin's mid-term question: could these replace some unit
tests?).

**A hand-authored keystone regression covers things a unit test structurally
cannot:**

- **End-to-end, cross-projection.** The transition runs through the real op
  dispatch and every wired projection (Turso CDC matviews, Loro CRDT, org
  writeback, ViewModel), then the full composed invariant catalog checks them all
  agree. A unit test asserts one function's return; this asserts *system
  convergence* after the action.
- **Oracle-checked, not assertion-checked.** You don't hand-write the expected
  output. The reference model computes it and ~45 invariants compare. That is why
  the block-to-page case doubles as an **oracle-gap detector**: it caught that the
  model itself is wrong, which an example-output unit test never could.
- **Free forward-compat.** As the model/SUT evolve, the entry keeps exercising
  the real code paths; it doesn't freeze a stale expected value.

**A unit test remains strictly better when:**

- **The bug is below the transition layer.** If no `E2ETransition` reaches the
  code (pure parser edge cases, a `PageId::for_path` corner, SQL builder quirks,
  a specific error *message*), a unit test targets it directly. Note the very bug
  here lives in `PageId::for_path` — the *keystone* can only reach it through
  `BlockToPage`, and even then the message differs by layer. `for_path`'s own
  unit test (`for_path_rejects_empty_segments`) is the precise, fast check.
- **You need speed / density.** Each hand-authored case boots the full SUT
  (~5 s). A unit test is microseconds. For a large truth table, unit/example
  tests win.
- **You need to assert an exact string/shape.** Invariants check *equivalence to
  the model*, not "the error said X". For "the message must read exactly …", use
  a unit test.
- **The layer isn't modeled.** Editor-internal behavior the transitions don't
  express (raw `InputState` keystroke handling, GPUI-only paint) can't be
  reached; drive those with their own slice/unit tests.

**Verdict:** hand-authored regressions are a strong complement, best for
*interaction/convergence* bugs that span layers and for locking dogfood repros
into the keystone with model-checked oracles. They do **not** replace unit tests
for sub-transition logic, exact-message assertions, or high-volume/fast checks.
Use them where the value is "this whole flow converges correctly", and keep unit
tests where the value is "this function returns exactly this".

## Limitations

- **Base state is fixed** (`wide_e2e_ref`). Shapes must be grown with
  transitions; there is no serialized bespoke initial state (ReferenceState isn't
  serde).
- **Only modeled transitions are expressible.** One `E2ETransition` variant per
  repro step; unmodeled UI layers (raw editor keystrokes, paint) are out of reach
  here — that's a keystone coverage boundary, not a harness one.
- **Stops at first failure** (fail-loud). Order green/liveness cases first.
- **Per-case SUT boot** (~5 s). Keep the sidecar to genuine locks, not a matrix.
  A batch / shared-boot mode (reuse one booted SUT across cases via `reset_vault`
  between them, like the live-MCP twin) is **deferred to Martin's morning queue**;
  until then, prefer a handful of high-value locks over a large table.
- **A case can be red for a shared-model reason** (as here): the red may land at
  the oracle rather than the SUT. That is a feature (it flags oracle gaps) but
  means "red" doesn't always mean "prod is wrong" — read the panic site.
