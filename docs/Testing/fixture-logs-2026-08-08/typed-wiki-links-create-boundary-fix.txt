B. WHAT IT DID NOT DO — the create boundary (ROOT CAUSE)
--------------------------------------------------------
A block BORN from UI input never reached that arm. The creation slot commits the
whole typed line through `block.create` (editor_view_model.rs: a creation
placeholder returns no `set_field` intent — "its text commits via `create` on
Enter"), and `create` was not parsed. Driven through the REAL dispatcher +
SqlOperationProvider + the real LinkSchemaModule:

    PROBE create: content="see [[Journals]] now" marks=None links=[]
                                            (lane-logs/t12-probe-create.log)

That is the dogfood signature exactly: raw text, NULL marks, zero junction rows
— and therefore zero backlinks and nothing clickable. The file the renderer then
writes still holds `[[Journals]]`, so the NEXT boot's re-ingest adopts it and
rewrites the stored characters.


C. WHY NO KEYSTONE DRAW CAUGHT IT (the escape, measured)

F. THE SILENT-REWRITE HALF, VERIFIED
------------------------------------
`adopted_create_content_survives_a_re_ingest_unchanged` renders what the store
now holds to org bytes and re-parses them: content and marks both come back
byte-identical, so the next boot's re-ingest finds nothing to change. The
keystone row proves the same end to end — its settle performs exactly that
write-back + re-ingest cycle and `inv-org-render-fixed-point` holds.

RESIDUAL, stated plainly: text typed BEFORE this fix is stored raw in existing
vaults, and the next ingest still adopts it. That is the documented adoption
contract, not a regression — but it means an existing vault sees the one-time
rewrite once more, after which it is stable.


G'. THE FIRST FIX WAS REFUTED — ADOPTION IS GATED ON ORIGIN, NOT ON SHAPE
-------------------------------------------------------------------------
The first version of this fix adopted whenever the create params carried no
`marks` key. Adversarial verification REFUTED that with a reproducible
counterexample, and it is worth stating why the inference was wrong rather than
just what changed.

`SqlOperationProvider::capture_row` filters `Value::Null` columns when it builds
an inverse. So the delete-inverse of ANY mark-free block — every block written
before adoption existed, and every block org ingest wrote — arrives at the
dispatcher as `create { id, content: "see [[Journals]] now" }` with no `marks`
key: byte-for-byte the shape of freshly typed text. `OperationEngine::replay`
dispatches exactly that. The guard passed, adoption ran, and UNDO restored
`"see Journals now"` + minted marks + a junction row instead of the bytes it had
deleted — breaking the identity-preserving inverse contract (ADR 0024).

The absence of a `marks` param is NOT evidence of unparsed user typing. Adoption
depends on PROVENANCE, which no shape test can recover. Both reds, and the A/B
that attributes them:

    undo_of_a_delete_restores_bytes_verbatim_even_when_adoption_would_apply
      left: "see Journals now"   right: "see [[Journals]] now"     <- CAUSED here
    undo_of_a_content_edit_restores_raw_previous_bytes
      left: "see Journals now"   right: "see [[Journals]] now"     <- PRE-EXISTING
                                            (lane-logs/t12-undo-RED.log)

    with the create arm disabled (lane-logs/t12-undo-AB-create-arm-disabled.log):
      undo_of_a_delete_... ... ok        <- so the create break is this lane's
      undo_of_a_content_edit_... FAILED  <- so the edit break predates it
                                            (links-increment-3, 2026-08-08)

FIX: `AuthoredInput::{Live,Verbatim}` is passed explicitly into
`OperationDispatcher::execute_operation_with_input`. The `OperationProvider`
trait's `execute_operation` — the entry `replay` uses — delegates as `Verbatim`,
so a replayed inverse is byte-identity-preserving BY CONSTRUCTION rather than by
a guard that has to be right. `DispatchingOperationEngine::execute_operation`,
the last holder of `OpOrigin`, maps `User`/`Agent` → `Live` and
`Rule`/`Sync`/`Ingest` → `Verbatim`, right beside the `stamp_provenance` call
that consumes the origin for the same reason. Both adoption arms (create AND the
older set_field one) are gated, so the pre-existing edit twin is fixed too.

    after: 10 passed; 0 failed          (lane-logs/t12-origin-fix-1.log)

Populations verified NOT in the class, with their call chains:

  - markdown ingest: identical chain from holon-markdown/src/params.rs:16
