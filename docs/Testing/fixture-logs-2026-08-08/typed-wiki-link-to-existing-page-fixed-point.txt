resolving path and rewrites byte-identical content, so nothing re-fires an

E. OPEN AFTER THIS LANE — escalated, not decided
================================================

The stores keep `Name` while disk carries `Scheme`. The design comment at
turso_seams.rs:186 expects a file re-ingest to "upgrade every store", but the
writeback's own write is echo-suppressed, so the upgrade fires only when
something else re-ingests the file (a later boot, an external edit). At that
moment the stored mark flips AND its `block_links` row flips from
`kind='page', target='Journals'` to `kind='block', target='block:journals'` —
a page-link becomes a block-link. Closing it is an architecture fork:

  (A) resolve at EVERY write boundary (dispatcher adoption AND provider-direct
      org ingest, else a hand-authored `[[Journals]]` reintroduces it);
  (B) stop emitting the resolved form: disk keeps the authored `[[Journals]]`,
      resolution stays in the junction (holon-api/src/inline_mark.rs:64), and
      docs/Explanation/DESIGN_LINKS.md §Phase 2-3 already says the rewrite
      happens on NAVIGATE, not on writeback. Against it:
      crates/holon-orgmode/tests/render_seam_resolves_link_marks.rs ratifies
      today's behaviour, and name-form links break across a page rename.

Recommendation in lane-report-21.md: (B). It is a user-visible semantics call.
