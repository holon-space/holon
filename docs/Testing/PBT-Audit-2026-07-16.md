## Annotation format (`@pbt`)

Sibling vocabulary to the existing `//! @c4` convention. C4 describes
dependency/deployment structure; test knowledge is *proof structure*, so tests
get their own keys. Annotations carry ONLY what code cannot state; everything
mechanical (invariant ids, cap requirements from trait bounds and
`cap_transition!`, caps provided by `impl SutX for Y`, `HOLON_*` env gates,
`#[cfg(feature)]` gates, wiring `Needs` declarations) is extracted by
`scripts/pbt_inventory.py` — never hand-maintained. Cap mentions are scanned
from code only, never doc comments (a stale doc mention must not fabricate a
requirement).

Grammar: `//! @pbt <key> <value…>`; continuation lines are `//!` followed by
two or more spaces. Keys:

| key | on | vocabulary / content |
|---|---|---|
| `oracle` | invariant bodies (repeatable for multi-invariant files) | `correspondence` (ref↔SUT), `construction`, `metamorphic`, `convergence`, `roundtrip`, `internal-consistency` (structural well-formedness needing no ref), `sut-internal` (SUT↔SUT — doctrine-suspect, must carry justification), `budget` |
| `covers` | any (repeatable) | `<slug> — <prod behavior / bug class this is the detector for>` |
| `slips-if-removed` | invariant bodies (repeatable) | concrete bug scenario that would ship undetected without this component |
| `rung` | transitions | driver-ladder rung: `ui`, `input-pipeline`, `intent`, `dispatch`, `mcp`, `external` (file/git-level) |
| `gen` | generators/transitions (repeatable) | distribution + shrinking notes, only where non-default (bias, gated arms, vocabulary coupling) |
| `overlaps` | any (repeatable) | `<other id> — why the overlap is intentionally kept` |
| `kind` | files outside canonical dirs | overrides path-inferred kind (open vocabulary; canonical kinds: invariant, invariant-wiring, transition, generator, sut-arm, ref, harness, module) |

Tooling: `python3 scripts/pbt_inventory.py all` →
`docs/Testing/pbt-inventory.yaml` (declarative inventory, 265 components,
193 annotated) and `docs/Testing/pbt-inventory.md` (per-kind tables, overlap
candidates by identical cap footprint, wiring-vs-body Needs drift check,
mermaid invariant→cap→arm graph). Script lives in repo `scripts/` because it
spans five crates. `extract` and `render` are separable; the table and diagram
are derived from the YAML, never from source directly.

## Findings (prioritized, verified)

### P0 — silent vacuity inside the keystone's required floor

> **Baseline-RED masking (2026-07-16 fix note).** The standard keystone carries
> ONE accepted baseline RED (the journals ingest-data-loss). Because proptest
> reports/shrinks the FIRST failing case and the journals blocks are in the seed,
> a journals draw diverges at the tick-0 `check_invariants` catch BEFORE any
> full-render case runs and before any sequence reaches `teardown`. So a
> newly-un-blinded render invariant that reds on a reached full_headless case —
> AND the F2 engagement floor (which lives in `teardown`) — are BOTH invisible to
> a standard run: it decides purely on journals. Validating F1/F2 through a plain
> standard run is validating through the mask. Bypass it with
> `PROPTEST_CASES=1 HOLON_PBT_FORCE_FULL=1
> HOLON_PBT_INVARIANTS='*match-ref*:skip,*block-content*:skip'`. This is
> documented at the top of `composed/harness.rs` so future lanes don't
> re-validate through the mask.

**F1. Two HEAD-catalog invariants are permanently vacuous in the wide
keystone.** VERIFIED. `inv-viewmodel-root-matches-render-expr` and
`inv-viewmodel-entity-ids-subset-of-data` early-return `Ok` when
`!ref_.has_root_render_expr()` (bodies at :99/:52); the wide run's default
3-column layout keeps render sources on panels, never on `root-layout`, so the
gate is always false there (the author's own note in
`main_panel_rows_match_focus.rs:35-41` says exactly this). Both sit in
`CENTRAL_INVARIANT_IDS_HEAD` (`catalog.rs:276,279`).
*Bug that slips:* a render bug minting a fabricated/stale entity id (the
`w4-web-05` phantom-row family) ships green through the ONE keystone —
`main_panel_rows_match_focus` does not backstop phantom ids.
*Fix direction:* return `InvariantResult::Skipped` from the gate (disclosure),
plus F2.

**F2. The non-vacuity floor proves "invoked," not "exercised."** VERIFIED.
`harness.rs:524-531` only asserts the id appears in `report.ran`;
`composition.rs:481-488` pushes every selected invariant's result — `Ok`,
`Skipped`, or `Fail` — into `ran`. An early-return-Ok or all-Skipped invariant
fully satisfies the floor. This is the doctrine's "selected ≠ exercised with
teeth" gap, live in the keystone.
*Fix direction:* floor on engagement — required ids must produce ≥1
non-Skipped, gate-passed verdict across the run (needs F1's Skipped semantics
first; small, independently landable).

**F3. Advice oracle: stage-2 collision has no floor and an empty-empty fast
path.** VERIFIED. `advice_rule_arm_reachable_in_default_mix`
(`generators.rs:1071-1097`) floors only that a rule block is *drawn*. Nothing
floors that `advice_expectation.scored` is ever non-empty (requires
ADVICE_TAG_POOL collision between the rule's tags and `SetEdgeField`-landed
tags); `advice_rows_woven.rs:249` skips empty-empty anchors, so an all-empty
run passes and `check_advice_relation` is never exercised.
*Bug that slips:* a weight retune or pool change silently vacuates both advice
invariants; a broken renderer weave ships while the rule-presence floor stays
green. *Fix:* a stage-2 floor test asserting non-empty `scored` frequency
across the default mix.

### P1 — coupling violations (SUT↔SUT where correspondence belongs)

**F4. `inv-task-state-storage-coherence` is SUT↔SUT and unanchored exactly
where it runs.** Double-sourced (invariants + SUT auditors, consistent
details). It compares SQL vs Loro task_state with no ref; the only Ref-anchored
task_state check (`viewmodel_state_toggle_correct`, `RefTaskState`) needs
`SutRenderer` and never selects in the sql+loro slice — the coherence
invariant's only home.
*Bug that slips:* a shared enrichment/CDC bug writes the same wrong task_state
to both stores; coherence stays green, nothing else looks.
*Fix:* add `RefTaskState` to its needs and compare both stores to the ref
(coherence between them then falls out); keep the fast slice.

**F5. `SwitchView` is fully vacuous.** VERIFIED. SUT apply writes a
harness-local `Mutex<String>` (`frontend_slice/components.rs:1948`), the
oracle reads the same field back; E2ESut arm identical (`RefCell` in
`test_environment.rs:2347`); `current_view` drives no production query or
render. The transition tests nothing.
*Fix (judgment fork below):* bind it to a real production view-switch path or
delete the transition — a green vacuous transition is worse than none.

**F6. Nav family rides the dispatch floor, and the archlint rule guarding it
never fires.** VERIFIED, with a refinement that changes the fix. `navigate_
back/forward/home`, `pin_block`, `unpin_block` call
`session.execute_operation("navigation", …)` directly. The chord
infrastructure exists (`op_write_cap.rs:234 send_block_chord`, used by
move_up/move_down) — but the production keybinding registry
(`holon-frontend/src/reactive.rs:1474-1502`) has NO nav bindings at all, so
faithful nav transitions are blocked on a *product* gap, not a harness gap.
Meanwhile `archlint/smells/focus.toml:21` patterns `execute_op\("navigation"`
and never matches `execute_operation(&EntityName::new("navigation")` — double
mismatch, rule dead.
*Bugs that slip:* today, nothing exercises any user-reachable nav path (there
isn't one — itself a product finding); once bindings land, a broken chord
route would stay green. *Fix now:* repair the archlint pattern (tiny);
*fork:* add nav keybindings to prod, then move the five transitions onto
`send_block_chord`.

**F7. Loro quiescence timeout is swallowed.** VERIFIED.
`quiescence.rs:52-56` eprintln!s and returns as-if-quiesced; all callers get
`()`; the eprintln bypasses tracing so `inv-no-observed-errors` cannot see it.
A hung sync surfaces as a confusing downstream mismatch or a false pass.
Direct violation of the repo fail-loud rule.
*Fix:* return `Result`, mirror `retry_until_ok`'s deadline error. Small and
mechanical.

### P1 — visible-red / gating defects

**F8. `inv-display-placement-canonical-inert` reds any full-frontend draw by
default.** VERIFIED. The body fails non-vacuity when no display-placed node
exists (`bodies/…:65-72`); injection is env-gated off
(`HOLON_PBT_DISPLAY_PLACED`, `frontend_slice/components.rs:1027`), but the
invariant is registered unconditionally in Strict mode (`catalog.rs:135`).
Any frontend/Turso wiring draw (~35% of valid draws) reds; the documented
`HOLON_PBT_FORCE_FULL=1` repro command reds every case. The only silencer is
the `HOLON_PBT_INVARIANTS` glob, which would also mask real inertness
divergences.
*Fix:* pair the invariant's selection with the same env that gates injection
(select iff injectable), or auto-set the injection env in the composed
builder. Do not solve it with the glob.

**F9. `SimulateRestart` is an org-reingest re-trigger, not a reboot.**
VERIFIED (narrowing an initial "no restart coverage" claim). It touch-writes
org files to re-trigger `FileSyncController` re-parse
(`frontend_slice/components.rs:2404-2453`); no Turso reopen, no Loro
rehydration, no engine restart — and its comment at `simulate_restart.rs:44-47`
falsely claims a DB reopen. The true persistence-across-restart class (source
of recent dogfood P0/P1s; `journals_restart_survival.rs` exists only as a
directed test) has zero generated coverage.
*Fix:* correct the comment now; *fork:* a real `RebootStorage` transition
(drop+reopen Turso handle, rehydrate Loro) — high value, medium cost.

**F10. `inv-sql-budget` is dormant unless `HOLON_PERF_BUDGET` is set** — the
p95<200ms SLO (a declared bug class) is not enforced by any default gate.
*Fix:* enforce a generous ceiling by default; keep the strict budget env-tuned.

**F11. No wiring-draw floor.** A default 16-case keystone run has no guarantee
any frontend/render wiring is drawn; render invariants can run zero times and
pass. *Fix:* assert a minimum wiring-family distribution per run (or pin one
case per family), same spirit as F2.

**F12. Dead root `Nextest.toml`** (live config is `.config/nextest.toml`) —
docs point agents at the dead one; its inert `retries` would mask PBT
non-determinism if "fixed" naively. *Fix:* delete the dead file, note in
DEVELOPMENT.md that PBT tests must never carry nextest retries.

### P2 — coverage holes (each with slip scenario in the inventory annotations)

- **F13.** `query_ast.rs` is dead: no generator ever constructs a `QueryAst`;
  nested-predicate SQL lowering unfuzzled. VERIFIED. Wire a generator into a
  watched-query transition or delete the module (fork).
- **F14.** `PeerCharEdit` generator returns `None` unconditionally —
  character-level concurrent CRDT text merges never generated (the OT case
  PBT exists for). Needs a ref model for char-merge or an explicit convergence
  relation (fork).
- **F15.** Watched-query generator is near-fixed (4 predicate shapes, one
  table, fixed columns); `QuerySource` file-generator mints 3 of 5 variants
  (`FocusRootDescendants`, `PageBlocks` unreachable via user-authored file).
- **F16.** Structural-chord sampling starvation: `move_up`/`move_down`/
  `indent`/`outdent`/`join_block` at weight 1 vs `split_block` 100 — the
  highest-value input-pipeline path gets ~1/180 of the mass. Cheap re-weight.
- **F17.** Settled-state blindness in `inv-main-panel-rows-match-focus`
  (self-documented): transient stale rows (the real `w4-web-05` linger)
  invisible at post-quiescence sampling. Needs a staleness-latency probe
  (relates to the latency SLO machinery, F10).
- **F18.** Two registry invariants (`block_ids_match_ref`,
  `block_tags_references_exist`) have no composed shim — absent from the
  keystone.
- **F19.** `HOLON_PBT_SHARED_TREE_MOUNT=1` is a standing dark arm (ref model
  lacks share-role support; leaving it on reds every run).
- **F20.** Vacuity cluster riding generator shape without floors: advice
  (F3), watches, nested-page seed consumers, rendered-toggle consumers.
  One floor test per cluster.
- **F21.** REF: `move_block` skips recanonicalization while every sibling op
  recanonicalizes. Verification narrowed this to a cross-content-type edge
  (recanon's secondary key preserves same-type order) with unproven live
  reachability — latent, not live. Unify the two sequence disciplines when

- **F22.** REF: `assign_reference_sequences_canonical` hand-mirrors

- **F23.** REF: focus is double-homed in the UI fragment
  (`focused_entity_id` per-region map vs `focused_block` global mirror,

- **F24.** SUT-1 (downgraded after verification): headless mirror==matview

- **F26.** Bespoke `assert_matches_reference` with 5s retry lives inside the

## Boilerplate consolidation

1. **39 hand-written `wire()` shims in `composed/invariants/`** re-declare
   Needs cap lists that the body's `where` bounds already state.
   `cap_invariant!` exists in pbt-core (`composition.rs:398`) and single-sources
   needs + lookups — but only pbt-core's own demos use it; the keystone bypasses
   it entirely (verified). Migrate shims to the macro. Constraint learned from
   the one deliberate mismatch (`viewmodel_decompiled_rows_match_query` adds
   `SutQueryResults` purely as a selection gate for degraded-twin exclusivity):
   any drift guard must be **containment (body bounds ⊆ declared needs), not
   equality**, and the macro needs an "extra selection gates" slot.
2. **`fn required_caps() { Self::declared_caps() }`** hand-copied in every
   TransitionFactory — fold into `cap_transition!`.
3. **Zero-field transitions** (11 files) repeat identical
   generator/factory/ref scaffolding — a `unit_transition!` macro.
4. **`.prop_map(|s| s)` identity maps** ×3 in generators.rs — delete.
5. **`frontend_slice/components.rs` is 4317 lines** — split by cap cluster
   once the c2-inc2 lane settles.

DOWN):

## Judgment forks (documented, not implemented — they change what the suite proves)

- **F5 SwitchView**: delete vs bind to a real view-switch command. Deleting
  shrinks the alphabet honestly; binding requires deciding what production
  view-switching even is (`current_view` has no prod consumer today).
- **F6b nav keybindings**: adding leader-chords for nav is a product-surface
  decision; the harness fix is downstream of it.
- **F13 query_ast**: wiring a QueryAst generator into watched queries widens
  the proof surface (predicate-compiler fuzzing) at generator-complexity cost;
  deletion is honest if watched-query fuzzing is deemed out of scope for now.
- **F14 PeerCharEdit**: enabling it requires choosing an oracle for
  char-level merges (shadow-mesh consumption vs convergence-only relation).
- **F9 RebootStorage**: a true reboot transition redefines "restart" coverage
  from re-ingest to persistence; medium build cost, touches storage handles.
