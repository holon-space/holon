# Holon observability — run records, report, and visual evidence

This directory is the **declarative, data-first** observability layer. Every
keystone / GPUI PBT run emits a machine-readable result *as a side effect of the
run itself* (no orchestrated second run); a collector converts those into
canonical YAML, a static report renders them, and a publisher uploads them to a
GitHub Release.

## Layout

```
.observability/               gitignored — the DATA (local, never committed)
├── runs/<run_id>.result.json emitted by the harness (green AND red)
├── runs/<run_id>.yaml         canonical YAML (yours to analyse)
├── runs.json                  cumulative index (the report's single fetch)
├── captures/<id>/             pixel frames + events.jsonl (GPUI capture)
└── captures.json              flipbook manifest
observability/report/         committed — the static report (HTML/JS/CSS)
scripts/holon_obs.py          collector + publisher
```

## Data model

- **`.result.json`** (harness native) → **`.yaml`** (canonical) → **`runs.json`**
  (derived mirror for the browser). The canonical format is YAML; `runs.json` is
  generated by the same code path, so they cannot drift.
- Every run record carries: `run_id`, `kind`, `git_rev`, `host`, `started_at`,
  `duration_ms`, `cases`, `verdict` (green/red), and `panics[]`. A red run is the
  point — the panic hook records the failure signature.

## Recipes

| Recipe | What it does |
| --- | --- |
| `just obs-collect` | Convert `.result.json` → `.yaml`, rebuild `runs.json` + `captures.json` |
| `just obs-serve` | Serve the repo root so the report + data are reachable locally |
| `just gherkin-replay-capture` | Run the GPUI Gherkin replay **with pixel capture**, then collect + serve |
| `just obs-push` | Upload `runs.json` + new YAMLs to the GitHub `observability` release |

Open the report: `just obs-serve` → <http://127.0.0.1:8000/observability/report/>

## Pixel capture (visual evidence)

GPUI PBT runs capture offscreen **pixel frames** via GPUI's
`HeadlessAppContext` + `MetalHeadlessRenderer` (the same seam Zed uses for
golden-image tests). Enable it by setting `HOLON_CAPTURE_DIR=<dir>`; the
`gherkin-replay-capture` recipe does this for you.

- **macOS only.** The Metal renderer is the only headless renderer upstream
  ships; on Linux `current_headless_renderer()` returns `None` and capture is a
  no-op (the run still emits its `.result.json`).
- Frames are `NNNN-<label>.png` + an `events.jsonl` manifest (one line per
  frame). The report's "Visual evidence" section is a flipbook scrubber over
  them.
- **Off by default, zero cost when off.** `HOLON_CAPTURE_DIR` unset ⇒ no capture,
  no I/O.

## History / direction of travel

The cumulative `runs.json` is the time series. Every numeric metric in a run
record is one point per run; the report computes slopes client-side, so "is it
getting better or worse" is literal, and any point drills into the run YAML.
